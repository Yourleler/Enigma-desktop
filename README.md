## 2. 整体完成后的使用体验

用户打开工作台，选择工程背景和允许范围，配置单模型或模型分工，然后交代目标，例如“升级服务接口，同步 SDK、调用方和迁移指南”。Agent 能识别相关仓库和消费链，先验证关键前提，形成轻量计划，再完成联动修改；暂存或提交后，自动给出与全量 diff 平级的智能阅读。重要改动由独立视角复核，最后执行真实联合验收，留下可核对的成果与完成凭据。

长任务运行时，用户可以随时问旁路“在等谁、有无有效进展、为什么慢”。开启托管后，独立管家根据明确证据处理失败、停滞或观测问题，保留原目标、当前文件、最新要求及已发生的操作。用户离开后回来，应能理解做到哪里、什么仍未完成、从哪一步继续。

需要并行工作时，用户新建特殊的“任务编排管家”对话，只说目标和限制。管家安排项目、独立工作对话、依赖、并发和模型，根据新证据调整分工，比较方案，选择成果并统一验收。普通 coding 任务仍可直接完成，不必经过一大套角色和设置。

## 3. 各个功能点子的最终期望效果

### 3.1 个人可用的 coding agent 与插件架构

**使用目标：** 从学习玩具升级为长期可用的个人工程工具，复用成熟 Agent 的模型循环、会话和界面，做自己的有效增量。

**最终效果：** 增量以宿主无关的领域模块、薄 Pi 扩展和必要宿主适配提供；不再维护重复的模型循环、CLI 硬渲染、复杂企业流程或无任务价值的管理功能。扩展能规范加载、共存、停用，停用后不破坏宿主工具集、会话和用户配置。用户允许必要架构调整；当前没有重新换到 DSH 的决定。

**验收标准：** Mac 上可以启动、配置模型、执行真实 coding 任务、重新打开旧任务；插件共存、加载/移除与 Pi 1.4.0 适配有证据。

### 3.2 多仓库协同改造

**使用目标：** 服务、公共库、SDK、应用、测试和文档涉及同一需求时，不反复切仓或重讲背景，也不只支持两个仓库。

**最终效果：** 动态加入多个仓库，记录角色与权限，发现声明依赖及实际消费关系，按上游到下游组织改动、契约、计划和检查。并发写入使用隔离工作区；成果先预览、检查冲突再选择整合。保留用户并发修改，上游变化使相关下游证据失效。联合验收实际运行消费者，不能凭“三仓通过”日志名认定全链正确。

**验收标准：** 至少三个独立仓库和跨语言案例完成同一需求的联动修改及实际联合验证；覆盖新增仓库、外部修改、依赖不明、冲突、取消和恢复。阅读→计划→改动→整合→验收→交付贯穿同一任务。

### 3.3 代码智能阅读：任务地图与变更阅读

**使用目标：** 看懂为何改这些文件、影响哪些入口/消费者，而不只是翻文件树或长 diff。

**最终效果：**

- 按任务组织“入口→接口→实现→调用方→测试”的阅读路线、仓库职责、关系与未覆盖部分。
- 按任务组织代码阅读，使用本仓阅读器与数据模型。区分源码事实、候选关系、静态推断和模型解释，结论可展开到实际源码位置。
- 暂存、提交或创建 MR 后生成固定版本的变更集；**智能阅读与全量 diff 是平级视图，共同对应同一版本。**
- MR 根据真实仓库的明确 base/head commit 获取来源，不能把新工作区内容混进旧 MR 阅读。
- 新修改使旧结果显示过期，历史仍可回查；解释失败时保留静态结果。

**验收标准：** 暂存 v2 后工作区改成 v3，diff 和阅读仍共同解释 v2；章节有锚点，直接/间接消费者可导航。支持现有 TS/JS/Python/Go 和接口 Schema 场景；阅读不代替业务验收。

### 3.4 时光机：模型主动纠偏与受保护代码恢复

**使用目标：** 模型意识到走歪、重复无效尝试或读入过多无关内容时，自己降低试错成本，带着教训继续。

**最终效果：** 同一次任务内选择有效旧上下文节点，说明失败原因、经验和下一步，自动继续。原始记录仍可审计，下一请求不继续背着无效模型/工具上下文。当前文件、原用户要求、更新后的计划、权限和累计用量保留。

Kimi D-Mail 的借鉴点是**上下文回溯**，不是自动撤销所有文件/外部操作。代码回退是单独受保护的动作：预览、检查当前版本和用户修改、确认旧执行结束，再恢复指定范围或新建 worktree 探索。不能用回溯隐藏失败、绕过权限、重放外部写入或清零预算。

**验收标准：** 真实模型走入被原检查否定的路线，主动回溯、留下教训，在同一任务继续并通过原检查；另测压缩、分支、最新要求、取消、并发编辑、部分恢复和未知副作用。

### 3.5 计划、原要求对账、独立验收与完成凭据

**使用目标：** 长任务和压缩后仍知道原要求是什么，区分“步骤做完”和“完整目标完成”。

**最终效果：** 每个对话有独立轻量计划、依赖、进度和验收缺口。原输入保留来源，压缩/回溯/Fork/交接/托管后重新对账。步骤完成需要当前实际证据；旧证据不能认证新代码。收尾给出“要求→处理说明→证据→版本→未知项”的完成凭据。

要求覆盖是 Agent 的明确判断，仍须独立复核；不能草率把复杂消息整体标成 addressed，或用 not-applicable 消除未完成项。局部检查可以优先，原联合验收保留；超时、失联和未执行检查始终显示为验收债务。

**验收标准：** 故意漏掉最新要求/验收会显示缺口；代码或环境变化使凭据过期；未决操作、未完成计划和未结算工人阻止完成。

### 3.6 项目记忆、中文召回与带条件的失败经验

**使用目标：** 后续同背景任务复用跨仓契约和有效经验，不重复调查，也不被旧经验永久限制。

**最终效果：** 可选轻量记忆，区分个人、项目、仓库关系、任务/分支和排障。先查小索引再读正文，支持中文、精确符号及来源/版本核对。一次性要求不自动成为长期偏好；用户纠正和删除优先，旧代码/会话分支不能恢复被忘记内容。

失败经验记录“这个版本、配置、错误下的方法为何失败，条件怎样变化后可以重试”，而不是永久禁用。只召回少量相关条目，去重、有界、按证据调整，不强制每轮反思/读全部历史。

**验收标准：** 跨会话中文追问能找到跨仓知识；私有任务记忆不串场；来源、配置和适用条件改变后旧条目失效；纠正/删除不随回溯复活。效果以实际使用衡量，不编造节省数字。

### 3.7 做梦 / Sleep-time 增量整理

**使用目标：** 大量会话/材料的整理不都挤在用户提问时，也不让后台整理成为无用开销。

**最终效果：** 选择少量有复用价值且当前有效的记忆/材料，在旁路有界整理；输出候选摘要、关联和矛盾，保留来源、适用条件、远端不确定性与用量。确认候选后才进入召回，不全量覆盖旧记忆、不自动改偏好或删除。来源更正/删除/过期后，派生摘要也失效。

暂停、取消、继续和重启保留用量；主任务需要资源时能让路。记录 helpful/irrelevant/wrong 的实际反馈，逐步优化材料选择和复用策略。

**验收标准：** 真实模型整理通过，暂停/恢复不清零预算、取消不晚发布；删除来源后摘要失效。收益计入整理、索引、检索和召回总成本。

### 3.8 旁路观察与慢任务解释

**使用目标：** 用户随时问“到底卡住还是在做有意义的事、在等谁、哪里值得优化”。

**最终效果：** 旁路不排入主 Agent 回合、不占工作区操作锁。覆盖模型等待/流式输出、工具/进程、依赖、记忆、审批、重试、快照、验收、压缩和采集/展示问题。分别说明活性、有效进展与未知，给最近可回查证据、等待对象和依赖来源。CPU、token、心跳只说明活动，不能证明有用工作或完成。

确定性查询无需模型，复杂解释有独立预算；无观测就说明未知，不猜隐藏思考。按阶段耗时和重复证据优化源码读、索引、快照和验收，保持外部修改检测。

**验收标准：** 正常长计算、静默命令、模型等待、重复失败、审批、压缩失败、取消/强杀时均能独立回答；缺来源/循环等待有可追查诊断。

### 3.9 广义托管管家与故障恢复

**使用目标：** 交代目标和限制后可以离开，回来不至于才发现某一轮压缩/工具/验证/展示失败后任务早已停止。

**最终效果：** 独立线程/进程持续监督，而不是只在主对话里多写几轮。诊断任意当前任务、模型、工具、依赖、审批、压缩、展示和观测问题，按证据与预授权选择等待、提醒、重建观测、结束旧执行并调整路线接续，或安排隔离维修。

明确错误循环可以否定方法，必要时结合时光机；昂贵验证可调整次序或调查替代路径，但保留原验收债务。缺终态查询时先补观测/通知方案，不能假装通过。组件有可复现缺陷时，在隔离工作区复现→修复→验证→预览→决定采用，不任意热改运行内核。

恢复确认旧执行终态、拥有者、范围与预算，保留原要求、外部效果和用量。不凭耗时长直接回滚、不替用户审批、不无限派生监督。宿主失联保留接管记录；重启只恢复已授权监护，不扩权或清零预算。

**验收标准：** 不误杀正常长任务；真实故障后接续原任务并独立核对；无法修复给原因和最小下一步。覆盖失联、重复副作用、并发干预、预算耗尽、停止/重启和隔离维修，不仅测重启率。

### 3.10 特殊对话：任务编排管家

**使用目标：** 从单个工作对话提取目标层管理，用户不用逐个建项目、开对话、设模型和协调。

**最终效果：** 管家作为原生特殊对话，按目标和限制创建项目、安排多个独立工人并发/按依赖运行、调整归属/模型/策略，利用旁路观察。根据新证据取消无价值支线、接续已有工作区、处理冲突、使用获准恢复；统一预览、选择、整合、原验收和汇总，不能凭工人自报结束父目标。

不固定角色流水线，也不限用户举例。初版管理自身创建的项目/对话；扩大到既有对话/外部Agent时明确所有权与授权。并发、任务数、仓库、模型和恢复限制约束正在运行的任务，收紧限制真正撤销旧权限。

**验收标准：** 真实工人实际并发，选择前原仓不变；项目归属、依赖、模型、取消、接续、重启、冲突选择和群体原要求/验收逐项证明。

### 3.11 多模型分工与 Loop 中途切模

**使用目标：** 建任务时配置决策、执行、复核的模型；运行中切换无需停止后重发整个目标。

**最终效果：** 单模型、规划/执行分离、困难时重新规划等策略可选；各角色模型、思考力度与预算可配置。Kimi规划/DeepSeek Flash编码只是例子，不写死组合。规划先读源码和建计划，不能经后台命令、配方、浏览器或委派绕过只读阶段。重要复核使用独立上下文与冻结源码，不是主对话换模型就算独立审查。

运行中选择在当前响应完成后的下一请求边界生效，保留原目标、权限、历史及累计消耗，显示当前/待切换状态。容量、协议、认证、取消、压缩、失败和预算可核对。小任务不强制分工。

**验收标准：** 同一任务实际切换请求模型；规划越权被阻止、复核只读、主上下文保留、预算不清零。受控协议与真实供应商质量/成本测评分别记录。

### 3.12 同背景新对话、Fork 与跨 Agent 交接

**使用目标：** 类似背景的新任务不用从头解释，也能转给其他Agent，背景复用不误启动旧目标。

**最终效果：** 区分沿用背景/继续原任务/比较方案；复用Pi fork/clone并补齐工程领域状态。上下文复制与代码隔离分开，原对话保留。Markdown+JSON包包含来源角色、原要求、新目标、版本/路径、计划、未解问题、材料/记忆范围、证据及最小下一步。

差量交接省去已共享的不变背景，仍保留原用户要求和当前来源。目标先核对代码与权限；历史证据不等于目标已执行，密钥、隐藏思考、私有状态和授权不自动迁移。Pi/Codex有具体适配，其他Agent按公开文本/文件接口逐个验证，不承诺所有私有状态无损转换。

**验收标准：** 同背景不同目标、继续、方案分支、Pi→Codex/回Pi、差量、缺文件、旧版本、忘记、角色保真和并行冲突分别验证。

### 3.13 文档编写与维护专精

**使用目标：** 文档让读者真正完成任务；代码改造后指南、接口说明、示例和排障文档仍准确，而不只润色。

**最终效果：**

- 按读者需求组织教程/操作指南/参考/解释，声明有源码、原要求或资料来源；区分已运行、静态支持、用户决定、推断、待验证，不从代码编造设计动机。
- 示例明确工作目录、输入、环境、命令、副作用和预期输出，并实际执行；优先复用现有验证器。
- 服务/SDK/消费者/文档共同迁移；没有参与写作的独立任务只拿必要背景和指南照做，发现缺失步骤。
- 同接口/术语/版本的明确文档矛盾可核对，历史版本不被误改。
- 源码/配置变化后定位受影响声明和段落，局部更新、重验例子，保护用户并发编辑。
- 文档与对应代码/来源/示例结果形成可预览下载的产物版本；以后HTML/PDF/DOCX出口必须真实渲染检查，当前不建通用办公平台。

**验收标准：** 三仓迁移指南有实际锚点和可执行例子，独立任务照做成功；故意变更源码/文档后旧声明/例子过期、同版本矛盾被发现，历史章节及并发编辑保留。

### 3.14 工作台层级、液态玻璃、动效与易用性

暂停时工作台/演示Mac应用可能仍开着，属于查看入口而非Goal继续执行。`localhost:38420/desktop/`使用隔离演示数据，不是实际项目全功能完成证明。
