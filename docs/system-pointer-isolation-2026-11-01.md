# 系统鼠标与可视操作指针分离

## 问题和目标

电脑插件应默认向目标应用发送后台输入，同时用独立覆盖层展示操作位置。用户自己的鼠标不应因为目标窗口在最前面而被移动。需要真实系统输入的操作必须明确告知并获得单次确认，应用访问许可不等于接管鼠标许可。

## 根因

接入的公开 Cua Driver 在坐标点击、拖动入口检查目标是否前台；若是，则自动改走系统 HID 事件，并先发送鼠标移动事件。这会改变实际指针位置，上层却仍将该动作显示为后台操作。可视覆盖层的运动动画没有调用系统鼠标移动接口。

本项目另有显式前台输入路径，用于后台输入无法完成的控件；此前模型可以自行设置 foreground 参数进入该路径，未单独确认鼠标接管。

## 修复

- 构建时移除已固定上游版本的两处自动前台路由。窗口是否最前面不再改变后台动作的输入路径。上游匹配点变化时构建报错，避免补丁静默失效。
- 保留每应用输入和 AX 控件操作、可视指针平滑运动、点击反馈与状态回读。
- 显式前台点击、双击和拖动在工具入口请求单次可见确认；拒绝、取消、无交互确认界面时不派发输入。模型不能以已批准应用或参数设置代替用户确认。
- 确认后仍检查当前租约、快照、窗口与取消状态。没有为了恢复手势而取消现有窗口保护。

## 实测

新建 AppKit 测试窗口一直位于最前面，可视指针开启。执行原生写值、按坐标保存、勾选、再次保存及按坐标拖动。每10毫秒采样一次系统指针位置，取得370份样本，最大位移0；回执确认文本和勾选状态实际生效。

拖动测试验证指针不被移动，不代表所有原生拖放控件支持后台拖放。拒绝每应用事件的画布或系统拖放仍需单次前台接管或由用户操作；不能将发出事件当作完成。

90项相关检查通过，覆盖驱动补丁、工具批准/拒绝/取消、macOS输入适配和可视覆盖层。完整类型检查通过，签名Mac包0.452.193已安装并启动。首次测试中的复选框坐标落在控件空白区域，修正测试坐标后实际勾选通过，保留原失败记录。

## 公开技术依据

- [固定版本 Cua Driver](https://github.com/trycua/cua/tree/d38bfbfb6b1d4296903477f517b1a0fa54af497b/libs/cua-driver)：MouseInput 的目标进程输入与前台 HID 分支。保留 MIT 许可及本项目适配说明。
- [OpenAI Computer Use 文档](https://learn.chatgpt.com/docs/computer-use)：macOS支持后台操作场景。公开文档没有说明其全部内部实现，本修复不宣称复用了其私有实现或达到全部相同行为。
