# 锁屏空闲开销与验收进程清理

## 实际问题与处理

正式240应用在Mac锁屏期间仍有持续的渲染开销。前端只根据`document.hidden`暂停Canvas，CSS背景动画也缺少系统锁屏的暂停信号。首个实现使用Electron的初始idle-state查询，但实机锁屏时返回了`active`；该失败保留，没有当作验收通过。

最终桌面宿主242监听锁屏、解锁、睡眠和恢复，并在启动/睡眠恢复时复用电脑助手的只读会话检测。原生探测实际返回`locked`，约0.5秒；没有启动电脑操控守护进程、截屏、请求新权限或派发输入，也不做持续轮询。只读检测与原有电脑操控的锁屏保护共用实现。

视觉暂停信号停止背景绘制、光照动画与CSS动画，保留最后的材质帧；不改动用户的玻璃、动效或背景偏好，不修改系统睡眠/锁屏策略，不暂停Agent、后台任务或媒体。解锁按原偏好恢复。迟到的启动探测和初始IPC回复不能覆盖较新的解锁事件；退出时清理监听。

依据：[Electron powerMonitor](https://www.electronjs.org/docs/latest/api/power-monitor)及当前安装Electron42的声明文件。实际观察显示初始状态查询不足以覆盖本机锁屏，因此增加了原生会话校验，未声称一个API适用于所有平台。

## 本机采样

使用相同正式配置和锁屏状态，以每秒一次的进程树CPU累计时间差与RSS采样。每个测量窗口约31秒，更新后先排除30个启动阶段样本；进程集合保持稳定。CPU百分比以一个逻辑核为100%，不是全机CPU占用。

| 项目 | 240样本 | 242宿主 + 241服务/界面样本 |
| --- | ---: | ---: |
| 进程树CPU | 9.05% | 3.25% |
| GPU进程CPU | 4.86% | 1.13% |
| 主渲染进程CPU | 3.04% | 1.19% |
| 平均进程RSS合计 | 659.8 MiB | 1126.7 MiB |

此处只证明本机这组锁屏样本的CPU下降，不能推广为全部使用场景的收益。**内存样本没有改善**；RSS含共享页面且受分页、压缩和加载阶段影响，不能当作物理内存占用或宣称内存优化。没有拿升级解包时间与普通启动混算，也没有将Electron单独的初始化日志当作完整界面可用时间。

另找到两个旧版本验收服务：它们的桌面所有者均已退出，无会话、无子进程。已停止服务，确认PID及监听端口消失，测试数据保留。这属于验收环境清理，不能计入产品代码优化收益。

## 验证与边界

96项相关检查通过，覆盖锁屏启动、运行中锁定、睡眠/锁屏组合、解锁、不可用检测、迟到探测、清理、前台原有动画节奏、原生助手构建与鼠标源约束、样式及持久化契约；三套类型检查与签名构建通过。

正式启动日志确认`suspended (locked)`。宿主242复用已签名的241服务和界面，避免重复更改无关后端；90项保护文件无缺失，模型、会话、草稿未变化，偏好仅更新时间戳。数据纪元仍为1。

真实的解锁事件恢复、前台动效目视和其他原生验收仍待用户解锁。这里只记录受控恢复回归和真实锁屏暂停/CPU采样，完整Goal保持未完成。
