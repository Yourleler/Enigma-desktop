# 文件预览刷新与保存归属

## 已复现的问题

文件刷新在读取完成后回写最初捕获的对象，可能把已清空的预览重新加入缓存，或覆盖稍后打开的较新版本。原回归没有覆盖这两种反例；新测试在修复前均失败。

远端刷新还会从正文响应、目录提示和已有记录中挑较新的版本号，再与本次正文拼接。正文与版本不属于同一次读取，可能错误描述当前文件状态。文本编辑器等待快照或附件读取后，也需要重新核对连接和文件身份，避免向新的操作位置继续写入。

## 修正

- 本地/远端刷新核对请求身份、服务器/工作区归属及当前文件版本，过期结果不再写回。当前标题等显示信息从最新对象保留，清空预览后不重新创建缓存。
- 同名连接的服务器或用户身份改变也会失效，不能只看连接名称。重试前再次核对，结束后释放刷新标记，避免累积或复用旧请求编号。
- 远端正文与版本只使用同一次响应；没有版本信息时保留原预览并显示可重试的刷新提示，不用目录事件的版本给不明正文背书。真实版本恢复后重读即可更新。
- 文本自动保存、排队保存、冲突重读和附件写入绑定原文件/连接；切换后不发起后续写入。已经发出的保存若迟到返回，不清除原恢复副本，也不把结果发布到新位置。
- 编辑器更新预览缓存前确认对应文件仍存在，避免清空后被保存回执复活。恢复副本、现有文件格式与保存权限不改变。

## 实际验证

在仓库外新建Markdown和隔离服务，使用真实文件接口；测试代理只在特定步骤去掉版本响应头，没有伪造编辑器或磁盘内容。

1. 初始读取真实原文后，在磁盘修改文件并移除刷新响应版本信息。界面显示“文件刷新未完成，当前内容已保留”，正文仍为原文。
2. 恢复版本响应头并点击重新读取，新磁盘正文出现，刷新提示消失。
3. 在实际编辑器修改正文，独立读取磁盘确认多行内容完整保存。
4. 仅把测试文件临时设为只读，再编辑。磁盘保持原文，编辑器完整保留草稿并显示保存失败；恢复权限后重试，磁盘内容与草稿逐字相同，保存提示消失。测试文件权限已恢复。

139项预览、HTML、编辑、持久化和恢复相关检查通过；最后清理重复逻辑后59项定向检查再次通过。覆盖等待快照时切换连接、迟到保存不能清掉恢复副本、复用组件不能把旧文档写入新路径，以及同名连接更换服务器身份。三套类型检查和界面构建通过。

上述证明本轮文本保存及刷新范围，不代表所有封面生成、复杂附件或原生Office组合均已重新验收。Mac仍锁屏，新版原生入口及原Goal其他待验项继续保留。测试代理、服务和网页已关闭；没有使用用户项目制造改动。
