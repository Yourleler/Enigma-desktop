# 管家资料传递与面板往返（265）

本轮补齐管家把指定资料交给工作对话、读取保存报告的链路，并修复窄窗进入工作对话后仍被右侧面板覆盖的问题。完整功能目标仍未完成，系统通知送达和更广的应用控制继续保留为未验收范围。

## 资料与报告

- 管家可列出本对话及其受管工作对话的文件，按文件标识选择输入；列表支持查询与继续读取。任意本机路径、无关会话和不属于本管家的任务不能作为文件授权。
- 安排任务时记录文件来源、摘要与大小，启动前重新读取并核对，复制到新工作目录后登记为该工作对话的附件。原文件保持不变；单任务最多16份、每份32MB，超过限制明确拒绝，不截断正文。
- 输入源发生变化、删除或失效时，不能继续用原资料证明目标完成。长中文文件名保留展示原名，副本文件名按字节限长并保留扩展名。
- 无代码仓库的资料任务使用独立工作目录和原生只读文件工具，无需伪造代码仓库。受管模型范围、请求额度及返回管家的导航仍有效，重启后也不能越过模型限制。
- `read-report` 支持列出和分段读取本管家或其工作任务的保存成果，返回来源有效性、检查证据和可继续传递的文件标识。历史报告不会被当作新的验收证明。
- 任务卡展示“指定资料”和来源，原工作任务结果、权限说明和验收状态分别保留。

## 面板导航修复

切换到工作对话时清除临时抽屉状态，窄窗显示聊天，宽窗保留用户的并排面板偏好。回到已经选中的对话也收起遮挡。

实测还发现，窄窗关闭面板后，点击同一个管家入口或侧边对话入口可能不展开。两个入口现在都经过统一的面板展开动作，明确传递用户意图；不再由分散的宽度条件直接修改左右面板。Esc关闭后可再次打开，宽窗保留左右同时显示。

- 管家、模型、资料和宿主关联检查161项通过；存储与构建关联检查77项通过。输入变更、无关文件、超限、跨受管任务资料选择和长中文名都有相应用例。
- 导航增量108项通过，扩展工程界面和布局回归278项通过，三套类型检查通过。Web在551像素窄窗验证管家打开、工作对话返回、侧边入口、Esc；1280像素宽窗切换后聊天和工作面板均保持可用。
