# 管家停止、接续与报告（273）

## 发现与修复

实际点击“停止此任务”后，工作模型请求断开、活跃数归零，但任务卡出现读取空对象的程序错误。原因是引擎取消流式任务时会把运行对象移出缓存，管家在结束时再次从缓存取对象，无法读取终态。

管家现持有本次运行的会话引用，在任务结束后读取同一对象的终态。新建和接续两个执行路径均已修正；没有改变取消机制、重新载入任务或自动重复操作。原读取证据、累计请求、任务和对话身份保留。

派发和接续确认框改用中文任务说明，逐行列明原要求、读写范围、模型、检查及资料，取消整段英文JSON的展示。模型提供的任务正文保留原文。

## 实际验证

- 通过Web新建主／子模型不同的管家，加入一个只读测试仓库，实际派发工作任务。
- 停止时观察到模型端连接中断，卡片从“正在停止”进入“已取消”，活跃数为0。修复前的空对象错误已复现，修复后消失。
- 同一个任务和对话接续，重新读取README。有效工具回执包含原文件哈希与全文片段。停止后仍显示该来源证据，再接续得到终态，累计模型请求从2递增到10，没有重置。
- 最终两次读取成功；最初三次测试模型使用错误参数，真实工具返回校验错误，保留失败记录，不计为成功读取。
- 最终任务为completed、无程序错误，工作对话身份未变，原仓库Git状态干净。UI“汇总为工作报告”实际生成并打开保存版本；报告仍明确原联合检查未执行，不把子任务结束当作整体目标完成。
- 管家相关20项定向检查及服务类型检查通过；新增一项覆盖新建／接续取消时运行对象被移出缓存的情况。客户端与服务构建、种子校验和完整Mac签名包通过。
- 正式273已安装，原生窗口确认加载273界面、原草稿与已打开文件仍在。768个保护文件无缺失，模型和会话文件未变化；隔离服务及模型夹具已停止，仅保留正常应用。

测试采用可记录调用的本机模型端点，证明运行控制和数据链路，不评价远端模型的质量。管家目前管理自己创建的任务；任意既有对话接管、全面应用编排、外部通知送达仍未因此验收完成。
