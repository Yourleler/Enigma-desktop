# 文件编辑草稿恢复

## 问题与行为

保存冲突时，编辑器虽然保留当前文字，但此前工作区持久化只保存文件位置和阅读状态。刷新页面后会重新读取磁盘，未保存的编辑内容随页面销毁而丢失。使用新建Markdown实际复现了这个问题。

200版在输入时立即写入本地恢复副本，适用于工作面板中可编辑的Markdown、代码和CSV。正常保存成功后只清理与本次保存对应的副本；晚到的旧请求不能删掉更新的草稿。恢复副本不会改变文件本身，也不替代正常版本化写入。

重新打开已授权文件后，若存在恢复副本，编辑器显示草稿并暂停自动保存，再读取当前磁盘版本用于比较。用户可以复制草稿、查看外部内容、采用外部版本，或者确认将草稿写回。写回仍检查当前文件版本，遇到新的外部改动继续阻止覆盖。同一文件存在多份恢复内容时可展开查看和切换；切换前会保留当前输入。

## 存储边界与兼容性

- 位置：当前浏览器/Electron界面的localStorage，键前缀`enigma-editor-recovery-v1:`，每个记录有独立ID。
- 字段：服务器/用户/工作区作用域、文件身份、文本、原版本信息与更新时间。不记录API密钥、连接令牌或预览签名URL。
- 服务器ID、用户、工作区与文件身份共同隔离；本机端口变化不作为新身份。工作区根路径参与隔离，避免不同项目的默认挂载和同名文件串稿。
- 新增独立恢复数据，不改变服务端会话或工作区偏好格式，不要求数据迁移。旧版本忽略该前缀；不删除旧版用户数据。
- 先写新副本，再清理上一份；空间不足时保留上一份，并明确提示复制当前草稿。恢复副本仍受浏览器存储额度限制，不能承诺无限文档备份。
- 只有在父页面成功读取文件后才恢复；不因存在副本绕过访问权限。副本不跨用户配置、浏览器profile或设备同步。
- 多窗口内容不自动合并。明确采用磁盘只清理当前选定副本，不删除另一个窗口的独立输入。
