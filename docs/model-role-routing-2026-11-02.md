# 模型角色与应用范围（待实现与验收）

用户新增要求：主Agent与子Agent可以使用不同模型；配置两种或多种模型后，输入区应反映角色与当前实际模型；应用范围不能只固定为未来工程任务。

当前代码核对：

- `ModelPolicyDialog`只有工程快照已连接且存在对话时才提供当前范围，否则锁定未来默认值。
- 规划／执行／复核策略、请求计数与边界切换目前保存在工程绑定中；普通对话已有独立的模型切换队列，但没有统一角色策略。
- 管家可给单个工作对话传入模型策略，普通子Agent可接受显式模型覆盖；两条路径没有共享的用户级主／子角色配置。
- 输入框只展示当前实际模型，尚未展示配置角色列表。因此“保存了多个角色”与“输入框能解释当前调用角色”不能混为已经完成。

后续实现必须满足：

1. 明确主Agent、子Agent和规划／执行／复核阶段的区别；每个实际调用可对应到角色及模型。
2. 支持当前对话、当前尚未发送的新对话、未来默认值；范围在对话／连接变化时不能误写。
3. 普通对话的模型设置不应创建虚构工程工作区，不改变记忆、文件权限或已有项目归属。
4. 子任务的显式覆盖、默认继承与管家允许模型列表有确定优先级；不能用回退模型掩盖配置不可用或越权。
5. 输入框显示配置角色与实际调用的模型，运行中调整保留已开始请求，并清楚说明生效边界。
6. 用至少两个隔离测试模型验证主子实际派发、阶段切换、取消、失败、排队任务与连接切换；仅保存表单不算功能验收通过。

该新增范围仍在实现任务中，不能当作已交付功能。既有全功能目标及未决原生验收继续保留。
