# 模型角色、侧边对话与管家入口

本轮目标：主／子Agent可以分别使用模型，输入框能解释配置角色与实际调用模型；普通对话和未发送的新对话也能设置应用范围。同时补回易发现的管家、侧边对话入口，修复浮层可读性。**这些增量不代表“管家已能控制全部功能”或完整Goal已验收结束。**

## 已实现的行为

| 范围 | 当前行为 |
| --- | --- |
| 模型角色 | 单模型、主Agent＋子Agent、规划→执行→复核、自适应返回规划；分阶段模式也可单独指定子模型 |
| 实际派发 | 主循环按当前阶段调用模型；新子任务继承配置的子模型，显式子任务覆盖优先；管家允许列表继续生效，不可用或越权不静默换模型 |
| 请求边界 | 已开始的请求先完成，待选模型在下一请求生效；当前模型、角色及待切换状态分别显示 |
| 应用范围 | 当前对话、本次尚未发送的新对话、未来新对话默认值及组合；普通对话无需创建工程工作区，保存时核对原对话和连接 |
| 预算 | 主对话与其独立复核计入该对话的请求上限；子任务保留各自预算，不能把调用次数误写成Token额度 |
| 输入区 | 多角色显示“主／子”或角色数量，可打开对应分工；实际模型按钮标明当前角色；Ferry等已有配置保留 |
| 管家入口 | 左侧常驻“任务管家”，首页和普通对话可创建；无工程项目时分配应用管理的独立任务空间；已有管家按钮进入工作任务 |
| 侧边对话 | 左侧快捷入口、右侧同级标签及加号恢复；有独立会话身份、输入、停止、模型选择与单次授权，可选择附带创建时的主对话文字背景 |
| 侧边文件 | 文件选择和拖入走侧边会话自己的附件登记；输入和附件草稿保存；历史使用原始文件名。可使用完整会话继续编辑 |
| 可读性 | 默认界面名称统一Enigma；引用使用引号、最多两行和全文提示；运行记录等浮层在顶层渲染，避免底层对话文字穿透；复制单项菜单缩紧 |
| 交互 | 设置光斑渐入至原峰值72%；新Fork标题带`fork-`；Esc只关闭当前菜单，不继续关闭背后的文件预览 |

普通对话的角色配置单独存储在插件配置中，不伪造工程根目录、不关闭该对话已有记忆、不扩大文件权限。管家工作对话的模型允许范围也覆盖新子模型，收紧到空列表仍可以撤回全部授权。

## 已取得的证据

- 隔离服务实际完成规划模型请求→`agent_phase execute`→执行模型回复，过程中没有工程绑定。
- 同一服务实际完成主模型派出只读子任务→子模型回复→结果返回主模型；工作文件没有因该测试改变。使用可记录请求的本机测试模型验证路由，不能据此评价不同真实模型的质量。
- 无源对话创建管家成功；普通对话通过Web创建管家成功并保留主／子模型设置。未自动启动工作任务。
- Web侧边对话实际上传、读取新建测试文件并接收回复；主栏保持原对话；刷新后继续显示侧边历史。首次发现附件标记格式不一致导致临时名泄露到展示，修正为主输入框格式后，最终刷新保留原始文件名。
- 262完整回归：12,215项通过、7项平台相关跳过；工程248项通过。后续附件／消息回归47项、浮层回归30项、Esc与菜单回归69项、模型／持久化回归45项通过。类型检查通过。
- 正式Mac已经核对管家和侧边入口、普通对话模型范围下拉，以及Ferry模型列表；没有把测试模型写入正式配置。
- 263原生运行记录浮层已不再透出背景文字，深浅主题均已查看；紧凑复制菜单已实机查看。264已正式签名安装，宿主／服务／界面版本一致；实机确认Esc关闭复制菜单后，原HTML预览仍打开。
- 正式资料更新前102项保护文件比对一致。最终再核对模型、配置、头像与会话文本11项，均与更新前相同；正常记忆整理、用量及界面时间戳仍会变化。测试中巡检误触关闭后已恢复原开启状态，浅色主题也已恢复。

## 仍需继续的完整目标

管家当前主要安排自己创建的工作对话。265已补指定资料／附件传递和保存报告读取，具体证据见[后续记录](conductor-inputs-and-navigation-2026-11-02.md)。不能据此声称所有应用能力都已经作为可编排动作闭环；更广的项目与侧边会话操作、通知送达及其点击返回仍需逐项验证和补齐。

本次新对话的分工先绑定当前待发送会话；应用重启前尚未发送的分工设置、完整侧边输入编辑体验、更多跨窗口拖放及原生纯悬停组合，继续纳入剩余检查，不能用现有正常路径覆盖。

系统通知中心先前的异常已恢复，不再为本轮验收操作该系统窗口或修改系统通知偏好。没有明确服务和测试范围的外部发送／付费生成不记为实网成功。完整目标继续按[剩余动作](acceptance-remaining-checks-2026-11-02.md)推进。
