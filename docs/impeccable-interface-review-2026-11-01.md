# 界面设计复审与修正

## 依据与范围

按用户要求查阅 [pbakaus/impeccable](https://github.com/pbakaus/impeccable)，固定参考版本为 [4f956490](https://github.com/pbakaus/impeccable/tree/4f956490f0056ae1ff5ea80372cf56e83c001d3c)。重点采用操作型界面的精确层级、熟悉控件、响应式结构、字段命名、状态反馈和动效开销指导。

这是根据公开指导进行的人工代码与渲染复审。没有安装或运行其自动检测器，也没有执行其双评审者 critique 工作流；不冒称 Impeccable 自动评分或完整 WCAG 认证。用户已授权修正问题，因此审查后直接实施必要修改。未将其提示词或源码复制到产品中。

范围为共享桌面/Web工作台、左右导航、管家任务、变更审查、设置的全部分类、主题/背景选项及助手风格选择。保留用户确定的液态玻璃、夜间极光和日间紫色。没有因通用“减少装饰”建议而关掉用户明确要求的材质与动效。

## 补充复审：文件操作与反馈（0.452.198）

- 文件列表约200px宽时，完整路径、自动整理和项目技能挤成多行，路径标签逐字断开。现在标题只保留可点击目录名和“目录选项”，其余操作收进既有玻璃菜单。目录说明、技能和完整路径仍可访问，菜单浮于滚动容器之外；Esc关闭并恢复触发器焦点。深浅主题实际检查通过。
- Markdown字数原先使用固定浅白底，在深色正文上突兀。改为无边框、无底色的主题文字和等宽数字，不再额外叠一层模糊。
- 后台命令退出成功原先写作“检查通过”，启动回执也会长时间保持“正在执行”。现在分别显示“执行成功”与“后台命令已提交”，提交时状态与当前运行记录明确区分，不暗示项目验收完成。
- 新建文档实测发现：外部更新首次阻止旧版本保存，但编辑器错误接受了尚未应用的新版本编号；下一次输入可能覆盖外部内容。修复后未解决冲突会暂停自动保存，并常驻显示外部版本、复制草稿、重新读取以及明确的采用/保存选择。覆盖或替换前给出确认；确认后的写入仍核对版本，再次变化继续阻止覆盖。
- 真实隔离服务暂停期间编辑文件、外部改写后恢复服务：修复前复现覆盖；修复后继续输入不会改变磁盘版本，界面草稿完整保留。复制内容一致，取消确认不写入，重新读取保留两份内容，确认保存后回读磁盘一致。此证据不等于冲突草稿跨应用重启已验收。
- 单独重建renderer会清掉另行生成的主题模块。本轮重打包曾因此导致主题尚未就绪，已补齐并新增构建拦截；缺少`lib/theme.js`时禁止继续生成服务包。最终Web深浅切换已通过。首个候选的宿主密钥集与签名归档不一致也被启动验证拒绝，按原签名流程重新构建宿主，未放宽验证。
