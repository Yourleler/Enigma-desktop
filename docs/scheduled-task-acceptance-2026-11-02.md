# 任务计划：保存、时间选择与真实执行验收

本轮补验完整清单 A42，并核对任务计划面板的材质和可读性。计划任务按时间触发；它与持续目标、旁路观察和任务编排用途不同。

## 实际发现

- 列表刷新会用任务对象重置正在编辑的名称、要求和时间，即使只是运行状态更新。
- 启停开关是按钮中的可点击 span，键盘无法独立启停。保存、启停、删除的异常没有就近反馈，HTTP 成功但业务返回错误也可能被当作成功。
- 模型目录加载失败会连带让任务列表无法显示；切换连接后的迟到查询也没有隔离。
- 时间选择浮层处于可裁切卡片内，旧底色与现有界面不一致。一次性日期输入仅监听 change，在实际浏览器输入后可能回到空值。
- 界面没有每个任务的运行历史入口，无法直接核对成功、失败和起止时间。暂停任务仍可能显示旧的“下次”时间。

新增反例先在修复前复现：草稿被刷新清空、缺少可访问开关、模型故障使任务列表丢失。之后通过组件和真实操作验证修复。

## 修复

1. 草稿与服务器配置分开。普通刷新保留未保存输入；其他写入改变配置后保留草稿并提示冲突。保存携带配置版本，存储层原子核对，旧草稿不能覆盖新配置。
2. 开关成为独立的键盘可操作控件。提交期间防重复，成功后确认结果，失败时保留输入。暂停明确只阻止下一次执行，不承诺终止已开始的任务。
3. 任务列表不再等待模型目录才能显示；连接和请求序号约束迟到结果，修改回执只更新对应任务，避免不同任务的回执覆盖彼此。
4. 时间浮层使用共用玻璃材质，脱离裁切容器并约束屏幕边缘。小时、分钟可用方向键、Home、End 选择，Esc 收起。表单区分“执行频率”和“时间”，空时间及非法间隔给出明确提示。
5. 任务展开后可查看最近 20 次运行，显示成功、失败、开始、结束及错误；可进入全部活动记录查看结果。服务端只允许读取当前已知任务的历史，文件读取失败不能冒充没有记录。

任务在应用服务运行时按分钟检查；退出或休眠不会在原定时刻执行。一次性计划执行后关闭。计划运行成功与产物验收是两种状态。

## 真实执行证据

使用隔离数据目录和新建工作目录，未向用户项目添加计划。

- 在 Web 创建一次性任务，要求只新建一个文本文件并回读。第一次因隔离模型目录配置不完整而失败，错误记录完整保留，没有算作成功。
- 补齐隔离模型目录后，通过界面指定实际模型并重新安排时间。调度器实际触发，工具记录包含 write、read 和文件登记。磁盘文件内容精确为 `SCHEDULED_OK_247`，没有末尾换行。运行记录从 09:13:58 至 09:14:10，约 12 秒；这是这次样本，不是通用性能保证。
- 界面同时显示成功和原失败记录，可跳转活动详情，展开任务要求及回复。一次性任务已自动关闭。
- 编辑名称后刷新，未保存输入仍在。另一写入更新名称后，保存旧草稿收到冲突；磁盘保持较新的名称。用户可明确放弃草稿并读取最新配置。
- 另建关闭的任务，键盘将时间从 09:00 改为 10:01，保存并核对。深浅主题菜单均目视检查，Esc 收起和删除此测试任务通过。

168 项任务计划、存储、路由、调度器和相关工具检查通过，三套类型检查与完整构建签名通过。模拟竞态和键盘测试不替代原生窗口验收；本轮未验证系统通知投递，也未扩称其他外部平台能力通过。
