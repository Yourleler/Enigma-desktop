# 智能阅读范围与结论可信度

## 本轮发现

此前文件片段补充只遍历前80个变更文件，后面的文件没有逐项状态。片段按6000字符截断时，只有一行的长文件可能没有标为截断。界面没有区分模型章节与程序生成的导航提示，普通代码还被按文件名统称为“核心代码”。

## 修正

- 每个变更文件都记录展开状态：符号片段、文本片段、已删除、不可读取或预算限制。已删除文件可打开旧版本；冻结来源没有保存文本时保留原限制，不伪装成空文件。
- 片段读取保留每文件512KB、整次64MB预算；预算以外的文件仍逐项列出。入口扫描和符号查询保留各自额度，并记录已检查候选数、实际查询数与待展开候选数，不把遍历候选说成已经解析成功。
- 片段因起始位置、行数或字符数不完整都会明确标记。90项变更记录的回归确认第81个以后的文本片段仍存在。
- “源码展开范围”区分有片段的文件与全部变更文件，明确不等于已审查或测试通过。旧记录缺少新字段时说明范围未记录，不从节点数量猜覆盖率。
- 展示既有静态关联分组，分组只使用已确认关系；独立文件仍单独列出，生成文件命名线索不豁免审查。页面按需继续显示文件与分组，避免一次铺满长列表。
- 程序生成的阅读顺序和章节标为导航提示，模型章节标为待核对建议；截断片段有提示。文件类型分组改成“其他代码”，不再暗示语义重要性。
- 阅读已有结果但没有分章说明时，提示查看范围、关联分组与关系图，不再错误提示尚未生成。任务地图与变更阅读共用范围和诊断解释，删去重复的诊断区。

新增`sourceCoverage`为schema 1中的可选信息。旧记录继续可读，旧读者忽略附加字段；阅读器版本摘要包含本次实现文件，后续重新生成时使用新算法。不迁移或改写用户旧报告。

Web实际展开两页以上的文件范围，末尾`note-84.txt`打开正文`Document 84`；删除文件打开旧正文。长单行显示截断；关联组展开后出现正确文件入口。阅读有结果而没有章节时，提示与实际状态一致。页面无横向溢出。
