# 多面板让位与可用宽度

日期：2026-10-30。原布局候选：**0.452.131**，已随 **0.452.133** 正式安装；宿主与服务协议不变。

## 使用目标与行为

导航、聊天、文件预览和工作台不能同时挤占正文，导致输入框和文字变成窄条。布局根据可用宽度决定并排、自动收起或临时浮出；保留草稿、预览标签、文件内容和用户选择的面板宽度。

- 并排时聊天保留至少 480 CSS 像素，预览至少 420 CSS 像素。空间不足先让导航退开，再收起工作台。
- 窗口小于 900 CSS 像素且预览打开时，预览占据主区，提供“返回对话”；返回只收起预览，保留打开的文件。
- 窄窗手动打开导航或工作台时使用浮层，背景暂不可操作。关闭后恢复交互；从浮层打开文件时，浮层自动让位。
- 窗口放大时恢复自动收起的面板，预留 48 像素余量，避免在临界宽度反复开关。用户手动关闭的面板不会因此自动打开。
- 保存宽度与本次受限宽度分开。缩窗不会把用户的宽度偏好改小，拖宽预览或文件栏时会重新计算其余面板。

用户要求参考 ChatGPT 应用的退避逻辑。本次工具禁止操作该应用自身窗口，未取得它的实操或内部实现证据；以上是本项目独立实现和实测的行为，不宣称复刻其内部规则。没有复制第三方源码或资产。

## 实现与实测发现

桌面与 Web 入口共用宽度计算、面板状态和拖动逻辑。重新计算覆盖面板打开、关闭、窗口变化、工程内容切换及拖动。删除工程组件中相互竞争的旧缩窗处理，给预览增加即时宽度上限。

实测中额外修复了两个问题：

1. 浮层关闭时恢复旧的 `inert` 值，会让刚打开的文档继续不可操作。改由各面板按当前状态管理可交互性，避免恢复过期值。
2. Web 预览延迟加载，可能错过拖动手柄的绑定。现在在实际手柄出现或被替换时重新绑定，同时清理旧监听和拖动遮罩。

## 验证

- **103 项相关回归通过**，覆盖宽度组合、恢复、延迟挂载、拖动清理、浮层、预览、Web 初始化和触摸导航。三套类型检查、界面构建通过。
- Web 实操覆盖 420、740、960、1280、1440、1920 CSS 像素的窗口变化。960 像素下最终实测为聊天 480、预览 480，两侧栏宽度均为 0。
- Web 拖宽预览至 780 像素时，工作台收起，聊天保留 660 像素。宽窗把工作台拖至 560 像素时，导航收起，聊天仍有 580 像素。重新缩窗后恢复为可用双栏。
- Web 从工作台浮层打开文件后，文档和聊天均可交互；返回聊天、重开文件与刷新后测试草稿保留。
- Mac 原生在隔离配置中完成双栏、系统半屏转完整预览、返回后草稿保留、文件浮层打开文档及查找操作。原生网页上的浮层层级经截图确认，测试表单输入保留。
