## 全量结果及实际修正

宿主与界面Vitest首轮共12,088项：12,069通过、12失败、7跳过。失败集中在四个检查文件，原始失败记录保留，不改写为一次全量零失败。

- 用量导出模块漏入导出清单。补登记`server/usage-export.ts`，不增加闭源依赖豁免；运行闭包同时登记该模块及已存在的观察进程会话读取依赖。
- 持久化指纹落后于实现。逐项核对六个来源模块：用量增加可选计时来源；变更来源增加可选仓库范围和未暂存来源；窗口快捷键、取消释放及返回管家的信息没有修改存储格式。保持DATA_EPOCH 1，更新具体存储契约与指纹。
- 新控件绕过共用间距、动画和遮罩变量。用量箭头、右侧标签、变更目录树、搜索框及快速聊天统一接入现有变量；遮罩沿用相同透明度，液态玻璃最大端点不变。
- 实际Web检查又发现“新任务模型分工”按钮沿用实色卡片底。改为透明常态，悬停/展开时高亮，补齐键盘焦点与展开状态；实际打开/关闭模型分工弹窗通过，没有修改用户模型设置。

另发现持久化扫描的12项临时豁免已到期。重新核对匹配位置、限定来源及调用方，保留辅助函数与多存储编排的区别；将目录创建、首次启动、旧迁移和配置迁移的操作种类收窄到当前实际使用范围，复查期限设为2026-12-01。此举没有完成流敏感归属分析，相关技术欠账仍保留，不能据此声称每个动态写入都已静态归属。

兼容性与失败项定向复跑13个文件114项通过，包含旧用量文件加载、写入新记录、重新打开后旧记录原值保留的检查。缺少计时来源的旧记录保持未知，不补造请求耗时。

工程模块使用独立的Node测试套件，原根目录`npm test`不会运行它。此次首轮从错误工作目录启动，241项中8项因CLI/扩展路径无法解析而失败；改为包目录执行后，**241项全部通过，无跳过**。

覆盖真实临时文件、Git仓库、子进程、本地HTTP模型协议、实际浏览器页面及工程状态，包括文件写入与拒绝、多仓消费链、联合检查、隔离整合、主动上下文回溯、旁路进程、资料与记忆、任务包恢复及取消。模拟模型协议的检查不冒称第三方模型实网效果；这些结果也不替代Mac原生操作验收。

增加根目录`npm run test:all`，依次运行宿主/界面与工程测试，均限制四个工作进程，避免今后遗漏独立套件或同时启动大量测试进程。
