# 旧对话自我介绍修复

## 原因

用户要求保留正常身份、性格、职责和能力介绍，只额外加入寄语。新对话的提示已修正，但旧对话保存的 `systemPrompt` 与 `finalSystemPrompt` 仍包含早期“自我介绍使用这句原文”的宿主模板。为保护旧会话上下文与前缀缓存，恢复时会优先使用冻结快照，因此升级后旧对话仍可能只回复寄语。

本轮在正式运行状态发现该现象，并确认冻结快照首行仍是准确匹配的旧宿主模板。之前仅验证新提示构造并不足以覆盖旧对话恢复。

## 修复范围

- 正常介绍与恢复修复共用同一段产品文案。
- 仅处理 Enigma 对话、提示开头的完整旧宿主模板，同时覆盖中文和英文。保留快照中原来的助手名称。
- 模板后的所有字节、追加提示、身份与人格文件、技能/工具快照和原消息记录均保持；不重新构建整个提示。
- 已有元数据写入队列和会话 manifest 保存修复后的提示；再次打开时不重复修改。
- 其他产品、已修好的提示、出现在引用或正文中的同一句话、以及不完全匹配的自定义说明均不改写。尚未打开的旧对话在之后恢复时修复。

## 证据

1. 在修复前增加真实恢复路径回归，旧 Enigma 快照测试失败，普通冻结提示测试通过。
2. 修复后 150 项相关检查通过：包括中英文、回车换行、完整余文与技能保留、幂等、自定义提示不变、基础/最终提示恢复及持久化。
3. 使用新建的合成测试历史，先放入三轮只有寄语的旧回复，再向同一个真实 Ferry 模型问“你是谁”。旧提示仍只返回寄语；修复后的提示正常介绍个人工程助手身份、源码/排错/测试等能力及验证方式，再附寄语。没有向正式用户对话发送测试消息。

该对照证明本次旧模板恢复问题已修复，不等于模型每次都会逐字使用相同介绍。用户新输入和自定义人格仍会影响回答。

## 兼容性

提示快照仍为版本 1，数据纪元仍为 1；只修改已确认错误的宿主文本，不引入新消息格式或新权限。存储登记与指纹已更新，恢复备份保存在仓库外。

本轮因发现此缺陷调整了检查顺序。原目标中的窄窗、纯悬停、系统通知与其余未完成入口继续保留，不能凭本轮修复结束全功能验收。

正式0.452.251已安装并启动。安装后对比备份：1份旧快照准确等于计划中的首行替换结果，3份其他快照未变，4份对话JSONL逐字节一致。宿主与服务重启时采用修复后的冻结提示，未向用户会话发送测试消息。

91项保护文件无缺失；模型、草稿与4份对话文件保持原样。预期的提示快照修正已逐字段核对，偏好只更新时间戳；后台记忆整理及其用量记录继续正常更新，没有回滚这些运行结果。
