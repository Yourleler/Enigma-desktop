# 用量记录：尾部箭头、请求明细与完整导出

本轮保留已有本轮、本对话、历史，以及时间、模型、用途、状态和对话筛选，补齐日常对账需要的细节。

## 展示和使用

- 轮次末尾不再显示像播放键的实心三角。数字后使用细线箭头，展开时转向，支持键盘与悬停说明；默认无底板。实时用量和按模型展开入口使用同类箭头。
- 历史轮次展开后显示输入、输出、总量、模型请求数、缓存与已报告思考用量，以及各模型分组。记录仍属于原轮次，下一轮不会替换它。
- 设置或本对话统计中的“请求明细”，可逐条展开已实测请求耗时、开始/结束时间、缓存读写、思考用量和请求编号；编号可复制。耗时包含请求等待，不当成纯模型推理速度。
- “导出”按当前筛选生成完整 CSV 或 JSON，包含全部分页。CSV 方便对账，JSON 同时保留分组汇总、筛选条件、导出时刻及记录保留范围。
- 完全没有上报用量的分组不显示成零消耗；请求导出保留空值。思考 token 不另加到输出，缓存不重复加到输入。展示最早保留时间与统计更新时间。

## 记录边界

导出从同一份账本快照生成，复用统计筛选与对话授权。全量导出不进入周期查询缓存；现有保留上限继续生效。导出权限与历史统计相同，范围不会因新增下载入口扩大。

文件只含用量与请求元数据，不含对话正文、模型提示、密钥、原始错误或本机对话路径。CSV 对可能被表格软件解释成公式的文本做转义。切换对话/连接/筛选或离开页面时取消尚未完成的导出，迟到响应不会下载旧范围。

这里统计接口报告的 token，不把实时估算混进历史，也不凭 token 数量猜测供应商最终账单。分支沿用的消息可以显示原轮次用量，但不会重复写入请求账本。

**耗时需要单独的来源证明。** 原生验收发现主对话的一些旧账本只在响应结束时即时写入，其“0 秒”实际是写记录的间隔。新增计时来源区分真实请求起止、仅完成回执与旧来源不明记录。后两者不显示或导出为已知请求耗时，起止时间也不伪造；列表保留原记录时间。已知辅助调用的开始/结束流程会保存真实计时来源。

## 验证

- Web 深浅主题：尾部箭头、展开/收起、键盘操作、轮次总量及请求明细通过。
- 隔离历史共 262 条：CSV/JSON 均导出 262 条，输入 2,502,887、输出 33,182、合计 2,536,069，逐条求和与界面一致。
- 用途筛选“辅助任务”后导出 15 条，合计 4,594，未混入其他用途。
- 正式原生界面：轮次展开/键盘收起、请求明细、复制编号、系统保存窗口通过；JSON 包含 51 条正式记录及 1 条缺用量记录，合计 287,543，与独立求和一致。发现旧记录耗时问题后补充计时来源回归，不沿用旧展示作为真实耗时证明。
- 回归覆盖完整分页、筛选、授权、未知用量、CSV 转义、迟到导出取消及已有实时用量行为；类型检查和签名构建同时执行。

最终 0.452.229 宿主、服务与界面已启用。原生再次确认历史请求显示“未记录（没有请求起止记录）”；实际安装服务导出 51 条记录，总量不变，旧记录起止与耗时均为空。66 项统计/界面/权限检查及 88 项主对话回归通过，三套类型检查与应用签名核对通过。77 项保护文件无缺失，模型、会话、草稿保留；正常记忆整理、版本代次和界面时间戳变更单独核对。

其他未验项仍按原完整 Goal 继续，不因这轮用量改进宣称整个产品已完成验收。
