# Markdown 封面交互与材质核查

本轮对应完整验收表 A36、A37、A44。范围是编辑器与阅读预览中的封面、图片解析、文件写入及菜单；不代替媒体生成服务或原生窗口的完整验收。

## 发现与修复

- 取消拖动、窗口失焦及无位移单击原本也会写入封面。现在两种视图共用拖动处理，松开且布局改变才提交，Esc、取消和失焦恢复起始布局。
- 只读编辑器原本可以通过右键删除封面。修改入口现在检查只读状态；只读菜单保留图片保存。
- 连续保存原本可能用旧正文覆盖其他修改。封面操作按文件串行，先读取最新正文和版本，只修改封面元数据；版本冲突最多重新读取一次，封面已被更换或删除时停止。
- 封面保存核对连接和原文件归属，迟到结果不重建已经关闭的预览，也不覆盖未保存正文。文件版本更新不再被误判成换了文件，不会清掉待重试操作。
- Web 编辑器原本把相对图片路径作为网页地址，真实封面出现破图。现在编辑与预览共用工作目录的资源解析，支持相邻目录图片；生成请求使用原工作目录目标，不能把虚拟图片路径当成本机文档路径。Web 封面可直接下载。
- 原封面菜单没有统一材质，编辑器菜单还依赖预览容器内的样式。两者共用浮层菜单，采用现有玻璃参数，支持键盘移动、Esc、焦点恢复和窗口边缘约束。
- 保存失败有就近说明和重试。停留文档顶部时，文件更新不再把用户跳到封面下的第一条标题。

最强液态玻璃端点、用户主题和用户文件均未为本轮测试改变。测试使用独立数据目录与新建文档。

## 验证

133 项关联检查通过，覆盖编辑、阅读、保存归属、只读、取消、冲突、菜单和远端资源。新增 Web 相对封面路径反例在修复前失败；整合过程中发现一次连接切换回归，修复后相关 42 项与上述 133 项通过。

实际 Web 操作使用真实文件接口，没有模拟文件保存：

1. 新建 Markdown 引用相邻目录 SVG。修复前图像宽度为 0，修复后编辑与预览均加载真实 960 像素宽图片，正文图片也可见。
2. 两次键盘调整将高度从 280 改为 312，磁盘内容一致。实际拖动最终保存为 372，文件顶部封面保持可见。
3. 测试文件设为只读后，写入失败，界面恢复原高度并提供重试。恢复权限并两次从文件外追加正文后，重试成功，所有追加内容原样保留。
4. 封面下载文件与源 SVG 的 SHA-256 相同。深浅主题菜单均目视核对，Esc 可以关闭。
5. 删除封面后独立回读磁盘：仅封面元数据消失，正文、正文图片引用及两次外部追加均保留。

拖动取消、窗口失焦及连接竞态的证据来自组件测试，不宣称为原生实测。模型生成仅验证请求目标和错误边界，本轮未调用真实图片生成供应商。

Mac 仍锁屏，原生封面拖动、Office 布局、悬停组合与完整目标中的其他待验范围继续保留；完整目标尚未完成。
