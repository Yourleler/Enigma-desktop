# 草稿保存、断线恢复与多窗口冲突

日期：2026-10-29。候选版本：0.452.121；服务协议 7，预加载协议仍为 6。此轮需要完整宿主/服务/界面一起更新，不能仅把新界面装到旧服务。

## 发现的实际问题

1. Web 桌面和移动页面使用另一条初始化流程，原来没有注册草稿持久化。真实 Web 输入后刷新即消失，服务端也没有草稿文件。已把该流程接到与桌面相同的草稿初始化与恢复。
2. 原保存只有 500 ms 防抖请求，没有本机副本。刷新、退出发生在请求前会丢最后输入；请求失败后只记日志，必须再次编辑才重试。
3. 多窗口只在各自窗口内串行请求，没有服务端版本条件。旧窗口可以把别处的新输入覆盖甚至清空。
4. 服务端把空文本视为删除，丢失只有技能/文件标签的富文本草稿；写盘失败前先改内存，可能错误反映已保存；缓存不检查外部恢复的文件。

以上为已确认的独立缺陷。历史正式草稿曾丢失的具体事件仍没有完整日志，不能宣称已精确归因。

## 当前行为

- 每次编辑先同步写入本机恢复记录，再排队同步到服务。记录按服务、工作室、用户、终端类型和窗口划分，不保存接口凭证；服务确认前保留最新完整文本与编辑器文档。
- 网络失败自动按 5–60 秒退避重试；恢复连接、窗口重新聚焦和上线事件也触发核对。页面隐藏/退出尝试 keepalive 提交；可靠恢复依靠已写入的本机副本，不依赖退出时请求必达。
- 每条草稿携带读到的版本；服务只接受对应版本的修改，清空同样受保护。409 冲突后停止自动覆盖，在输入框附近显示“比较版本”，用户可使用已同步版或保留当前输入并同步。
- 重新聚焦读取新版本时，不偷偷提升仍显示旧内容的编辑器版本条件。旧请求收到的确认也不能删除新编辑产生的恢复记录。
- 本机恢复容量失败显示明确提示，不能声称“已存本机”。服务拒绝过大的新草稿或第 201 条会话草稿时保留原数据和本机副本，不静默截断/淘汰该次请求。
- 空文本但包含有效富文本标签会保存；只有真正空的文档才删除。服务先原子写盘再更新缓存；外部草稿文件变化会使缓存失效。
- 草稿状态与冲突比较以内联区域展示，不弹窗、不阻断继续输入；可查看尚未同步的恢复副本。首页和已创建会话使用独立键。

使用全新测试目录、浏览器页面、空白会话和原创中文输入。为创建空会话设置了指向未监听本机端口的测试模型描述，没有进行推理，也没有修改正式配置。

## 使用边界

本机恢复副本属于当前浏览器/桌面 profile 的 localStorage，清理该 profile、站点数据或损坏存储会失去副本；隐私模式不提供跨整个浏览器退出的长期保证。未同步记录会保留至成功确认或用户明确选择版本，不能无限保证浏览器存储容量。

同步冲突协议在新版客户端间生效。旧服务不支持条件写入时，新界面仅保留本机副本并提示更新；旧客户端的兼容写入仍是旧行为，因此桌面交付使用完整版本。附件上传/语音录制属于各自文件生命周期，此轮保存输入文本与编辑器文档，不宣称把未完成上传的二进制文件一并恢复。

旧读取归一化仍兼容历史容量和格式；此轮保护针对新版保存请求。仍保留总体 Goal：各预览/浏览器的原生组合验收、正式应用更新以及后续发现的成熟度缺口。
