# Enigma 功能组合与后续打磨路线（2026-10-26 头脑风暴）

基于 README §4 的点子表，结合本轮已落地的实时 token 计量、液态玻璃工作台、
运行时切模/多模型规划、多仓协同、智能阅读、时光机、记忆/做梦、旁路管家、
任务编排管家、文档专精的现状，给出"哪些组合现在就能产生新价值"和
"下一轮该打磨什么"。优先级按 用户可感知价值 × 实现成本 的性价比排序。

## 一、值得做的功能组合（妙点）

### 组合 1：实时 token 表 × 多模型分工 = "模型性价比仪表盘"（P0）
- 每个角色（规划/执行/复核）的 ↑输入/↓输出、缓存命中率、单请求成本分别累计；
  adaptive 模式触发 replan 时在仪表盘上标注"为何换模型、多花了多少 token"。
- 用户能直接回答："规划模型比执行模型贵多少？复核值不值？"——
  这是 README §3.15"计入实际成本不用行数"的 UI 落点。
- 依赖：meter 已有 run 级累计与 cacheRead/cacheWrite；差一个按 role 分桶
  （meter 已带 model 字段，前端按模型聚合即可）。

### 组合 2：token 表 × 时光机 = "回溯不浪费"（P0）
- 时光机回溯本身要重发上下文。回溯发生时 meter 标记一段"重试消耗"，
  和被丢弃路线的 token 对比，让用户看到纠偏省下/多花的量。
- 记忆里把"高 token 低收益"的失败模式沉淀为带条件经验，正好接做梦整理。

### 组合 3：旁路管家 × token/等待关系图 = "慢在哪"一键诊断（P1）
- 旁路现在能答"有没有有效进展、在等谁"。把 meter 的阶段时间线
  （upload TTFT、thinking、writing、tool）喂给它，诊断从"卡住了吗"
  升级为"卡在首 token 3.2s（模型排队）/ 工具锁等待 / 依赖未装"。
- 现场修复后自动在 meter 上标注干预点，事后可复盘。

### 组合 4：智能阅读 × 文档专精 × token 表 = "变更说明书自动生成+成本可见"（P1）
- 暂存/提交产生变更集后，一键让文档专精基于智能阅读章节起草迁移指南，
  meter 实时显示这次文档生成花了多少 token；示例执行结果回写文档版本。
- 正是 README §3.13 的核心闭环，也是文档 r5 未竟部分最实用的切面。

### 组合 5：多仓规划 × 等待关系图 = 跨仓并行甘特视图（P2）
- conductor 已有依赖序和并发上限。把每个 worker 的阶段时间线按仓库泳道画成
  任务型工作台 风格甘特/时间线，阻塞边（等事件/等 PR/等验收）可视化，
  对应 README"等待关系图展示事件产生者"。

### 组合 6：记忆做梦 × 模型对照 = 用便宜模型筛、贵模型定稿（P2）
- 做梦增量整理用 utility 模型做去重/初筛，候选确认前用主模型判质量，
  成本可从 meter 验证；这也是 §4 已列点子的落地方式。

### 组合 7：token 表 × 预算/审批 = 超额前的温柔提示（P2）
- 任务级预算（model-policy 已有 maxRequests）接近上限时，meter 胶囊变色，
  而不是等请求被拒；和审批流联动成"再花 N token 需要确认"。

### 暂不建议做
- 复杂的多 Agent 3D 可视化、自动 git push/发版：README 已明确红线，
  收益低且风险高。

## 二、功能本身还要继续优化的点

| 功能 | 现状短板（本轮实测/走查发现） | 建议 |
|---|---|---|
| 实时 token 表 | Gateway 链路上行长时间显示 0（首包前上下文用量接口未就绪），本轮已用 tick 内补估算缓解，但 provider 真值全靠末包 | 推动拿到首包 usage（input）后立即翻转；长 TTFT 时显示"排队中"而非干等 |
| 液态玻璃 | 玻璃效果目前只覆盖工程工作台浮岛；聊天卡片/弹窗仍是旧材质 | 下一轮把玻璃语言推到会话气泡、设置弹窗；同时做一次高光/折射强度的真机校准 |
| 窄窗 | 860px 抽屉已可用，但抽屉打开时没有遮罩/点外部关闭 | 加 scrim + 点遮罩收起 + Esc 关闭（手机端体验关键） |
| 智能阅读 | 入口较深（要先生成变更集） | 欢迎页/变更视图加"当前分支相对 main 的变更"一键入口；MR base 用文件夹选择器（preload 已暴露 selectFolder，ConnectDialog 还在手填路径） |
| 运行时切模 | UI 入口在输入框和模型分工弹窗，切换后的"下一请求生效"状态不够显眼 | meter 胶囊已显示当前模型；补一个"已排队切换到 X"的轻提示 |
| 旁路/管家 | 真实启动走独立进程，冷启动成本高 | 与"真实 profile 冷启动慢"（file-history watcher 风暴）一起做观测采集懒启动 |
| 代码 | 工程 TSX 已 prettier 化；host.ts 等仍有深嵌套 Proxy | host.ts 的 scopedFactory Proxy 可拆成具名包装函数；enigma.ts 薄路由已较干净，保持 |

## 三、建议的下一轮顺序
1. P0：model 分桶的性价比仪表盘 + 时光机重试消耗（都建立在本轮 meter 上，成本低）。
2. P1：窄窗遮罩/关闭手势；旁路"慢在哪"诊断；文档×阅读一键起草。
3. P1：真实多仓 + 真实 Gateway 的端到端回归（完成 README §5.1 欠账，含 r5 文档收尾）。
4. P2：跨仓甘特、预算温柔提示、做梦分级模型。
5. 发行前：最终 Mac 包 ad-hoc 启动验收；只做本机签名/打包，不自动发版。
