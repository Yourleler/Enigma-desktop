# 界面设计原则

本项目以清晰、克制、内容优先为方向。以下是结合Apple官方设计指南形成的项目约定，不代表已实现原生系统控件，也不是把每个区域都改成玻璃。

## 层级与材质

- 正文、代码、图片和用户正在编辑的内容优先。导航与操作帮助定位和处理内容，不应比内容更抢眼。
- 窗口使用一条应用顶栏和一条常驻外侧工具栏，内容在统一圆角工作区内分列。合并入口时必须显式分配最小宽度和收纳规则，不能依靠flex挤压后任其重叠。
- 布局/材质变量由Web与原生共同入口加载；主要面板统一留白，不把原生的样式文件当作Web必然存在的依赖。
- 同一层级的控件共用线宽、尺寸、颜色和状态。不要给每个图标增加白色底块、亮框或阴影。
- 列表内操作默认采用无边框、中性色图标，悬停/聚焦才提供轻微反馈。选中状态使用主题强调色；颜色之外也有位置、形态或文字提示。
- 液态玻璃用于确实需要区分前后层级的关键控件和临时表面。静态文字预览优先使用保证阅读的普通材质，不加额外折射和强高光。
- 不削弱用户选择的最通透端；组件需要接入统一材质参数，不能另用固定不透明度造成不一致。

## 图标与可操作性

- 熟悉的动作使用容易识别的图形。统一采用项目自己实现的简洁图标，不复制其他产品的私有素材。
- 归档是可恢复动作，默认使用中性色；红色留给真正具有破坏性的操作。
- 控件视觉尺寸与命中范围分开考虑。桌面可以保持图形轻巧，触控环境增加命中范围；不能通过把线条画粗来假装更容易操作。
- 自定义按钮必须有悬停、键盘聚焦、按下和需要时的选中状态。隐藏操作仍能通过键盘或触控到达。
- 图标按钮提供简短、具体的提示，例如“移入归档，之后可恢复”。提示只解释当前控件，不堆叠整个功能说明；状态改变时提示同步改变。

## 导航与动效

- 对话刻度是次要定位工具，采用短小、无底框的细线区域，不能占满整面侧边。大量轮次通过独立滚动保留，不抽样丢失入口。
- 当前阅读位置用颜色和适度加长标记。悬停只做小幅形变，避免大光晕、粗胶囊和夸张弹跳。
- 预览按需出现，包含时间与实际内容，约束宽高并可内部滚动，不影响正文布局。
- 动效服务于状态变化与空间关系；支持减少动态效果，不用持续闪烁或循环装饰表达所有状态。

## 验收

每次改动都要在真实页面核对深浅主题、正常/悬停/选中/按下/焦点状态，以及窄窗、长标题、长对话和菜单边界。浏览器与原生共用实现不等于两端都已实测，记录需分别注明。已有动作和数据保留必须同时核对。

## 公共依据

- [Apple：Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：强调明确动作、熟悉图形和按下状态；macOS图像按钮通常不需要系统边框，但要保留足够命中空间。
- [Apple：Offering help](https://developer.apple.com/design/human-interface-guidelines/offering-help)：提示应短暂、简洁、聚焦当前控件，并描述它触发的动作；可随状态变化。
- [Apple：Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：材质用于形成层级；自定义液态玻璃应克制，文字较多的临时区域应优先保证对比度。
