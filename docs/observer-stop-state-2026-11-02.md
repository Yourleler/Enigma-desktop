# 旁路诊断与观察终态补验

在已有隔离任务上实际操作“运行状态”，没有启动或改写正式用户任务。

## 实际检查

- 事实区显示会话空闲、来源进程存活与观测正常，20条历史操作单独列出。
- 独立诊断模型请求成功，返回当前没有主任务运行的证据，并说明历史服务/代码阅读状态不能证明当前文件通过检查。输入3476、输出348个已报告token；诊断期间主对话仍空闲。
- “观察并给建议”实际启动独立进程，状态为watching，操作系统确认进程存活，干预次数0。
- 点击停止后原观察进程退出，主任务仍空闲。没有把一个按钮回执当作进程已停止的唯一证据。

## 发现与修复

停止后宿主释放内存中的进程句柄，状态接口返回null，界面重新显示“尚未启动”，保存的终态也不再显示。

现在对已经配置过观察的会话读取保存的状态；使用与记录一致的原始对话编号，不混用宿主定位编号。读取历史停止状态不创建或加载Agent运行时；未恢复的有效托管授权仍明确显示宿主不可用，不伪装为正常停止。

服务器重启后接口返回stopped、干预0，原进程仍不存在；实际Web界面显示“已停止观察”，并保留重新启动入口。26项相关回归与三套类型检查通过，完整235签名包构建通过。

## 验证边界

本轮证明了独立咨询、空闲判定、观察启停与保存终态的链路。没有重复测试所有托管维修或自动恢复场景，既有授权/取消测试仍按原证据范围保留。Mac持续锁屏，原生状态面板及其他原生项目继续待验，不能结束完整Goal。
