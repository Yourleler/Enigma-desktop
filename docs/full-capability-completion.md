## 推进顺序

先完成模型主动回溯及其真实模型验证，再建立版本化变更阅读/全量 diff 共同基础，同时梳理任务与内容导航。随后接入模型策略、记忆整理、要求/等待/交付机制、文档维护及跨 Agent 接续。广义托管基于这些运行事实建立独立监督与有界动作，并测试正常长任务、异常和用户接管。最终统一做视觉、交互、完整工程回归、宿主回归、打包与真实多仓任务验收。

托管范围不限压缩，但动作仍遵守当前授权、所有者身份、旧执行终态与原成功标准。已发生的外部写入不能假装撤销；未知效果先取证。自动改代码的维修要在隔离工作区完成并验证，不直接修改任意 live 内核。此边界用于实现完整可靠流程，不把广义管家缩成单一压缩重试器。

领域能力与界面依据本项目需求实现，不纳入第三方私有源码、样式、提示词或协议。新能力按完整场景记录收益和失败，没有实测的数据不编造。

## 任务编排管家：追加范围与首轮实践

用户进一步要求把管家提为特殊对话，而非仅在普通工作对话内监督。它接收目标与限制，通过可组合动作创建项目、安排独立工作对话、依赖/并发调度、设置模型角色、运行时切模、归属调整、状态观察及授权恢复。用户列举场景是建议，能力可用于方案对照、独立验证、验收边界审查、研究汇总、代码/文档协作等其他任务。

首轮实现位于 `plugins/enigma/conductor.ts` 与宿主适配：特殊对话只管理自身拥有的项目/工作对话，工人使用隔离 worktree 和写入子集。模型可以收紧限制，扩权需要明确用户配置。创建阶段顺序化，执行阶段有界并发，避免共享宿主焦点/创建状态竞争。

真实 Gateway 首轮在 `conductor-practice-r3/report.json` 通过：创建一个原生项目及两个只读工作对话，分别核对函数链与验收范围；两者的实际运行区间重叠，项目归属有效，原源码保持不变。实际发现原示例检查只覆盖文本值，不能证明函数消费链。这说明管家可组织互补检查并指出验收缺口；该案例不证明自动集成、冲突回溯或所有托管故障已经完成。

模型主动回溯证据：`Documents/Codex/2026-10-25/enigma-desktop-completion/native-time-machine-r1/report.json`。暂存阅读证据：`Documents/Codex/2026-10-26/enigma-desktop-completion/native-smart-reading-r2/report.json`，生成上游改动、直接消费、间接消费三个中文来源章节。运行中切模协议证据：`model-switch-r1/report.json`，两种受控模型在同一次任务中切换；它不是 Kimi/DeepSeek 的效果测评。

这些是当前里程碑，整体 Goal 继续。尚需重点补：模型策略的专项/真实联调、管家持久接续与独立监护控制、写入/冲突/恢复实践、成果集成及原联合验收、记忆/文档等其余范围、完整产品视觉与交互、构建与最终回归。
