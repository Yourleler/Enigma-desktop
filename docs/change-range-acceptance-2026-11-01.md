# 对话变更与Git范围验收

## 实际场景

使用新建目录和隔离应用配置，真实模型执行两轮文件操作。第一轮修改文本、新建文件、删除文件、重命名；第二轮再次修改文本，生成520,000字节文本和4字节二进制文件。目录始终没有初始化Git。第三轮模型只回复文字，在捕获窗口内由独立程序改写文件，以检验归属信息。

- 第一轮显示4个变化，普通文本为原始→第一轮；重命名前后内容一致。
- 第二轮显示3个变化，普通文本为第一轮→第二轮；大文件/二进制保留变化记录而不伪造正文。
- 整个对话显示累计6个变化，普通文本为原始→第二轮；选择第一轮后仍能回看冻结内容。
- 第三轮外部程序的改动显示“归属待确认”，没有认作已核对模型写入。脚本检查了运行中的捕获记录后才写文件；较早一次错过窗口未做写入，未计作成功。

另建Git仓库，保留两个提交、暂存版本和未暂存版本共四个不同内容：

| 选择范围 | 实际读取 |
| --- | --- |
| 已暂存 | committed → staged |
| 未提交 | committed → working |
| HEAD~1 → HEAD | base → committed，及长文件第3行和第1100行的两处变化 |

长文件1,200行，折叠显示两个变化块；展开全文后可跳到第1100行。无效提交名称报告错误并保留已读差异，修正后可重新读取。所有操作仅在新建样本上进行。

## 修正

- 重命名不再沿用M标识，列表显示R，正文标题显示原路径→新路径。
- 对未保留正文的文件隐藏双栏、全文、查找与跳转按钮，移除上一文件残留的变化计数，显示前后字节数和具体原因。
- 写入归属常驻于差异正文上方，窄栏也不会只剩隐藏提示。
- 初始目录请求晚到时不覆盖用户刚选择的来源；提交/轮次依赖目录信息时先等待加载。
- 无效提交有中文恢复指引，折叠的相同行数使用正确的上游短语键显示中文。
