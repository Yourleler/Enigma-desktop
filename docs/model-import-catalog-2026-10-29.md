# 本机模型导入修复

日期：2026-10-29。影响 `scripts/enigma-profile.mjs` 及 `--models` 启动参数；不修改现有正式配置。

已迁移的数据目录从 `provider-catalog.json` 读取供应商，原导入脚本只写 `added-models.yaml`，导致导入显示成功但运行时没有模型。现通过 ProviderCatalogStore 写当前目录；按供应商/模型 ID 合并，保留未导入的模型、已有角色、能力与未提供的凭证字段。导入模型的上下文、最大输出、协议和图像输入能力保留。

先验证完整导入，再写入；无模型、错误接口地址、无效模型条目会报错，既有配置不被替换。写入前将当前目录与助手配置备份到用户数据目录的 migration-backups，使用仅所有者可读权限。旧供应商文件不重写，既有角色默认模型不重置。

10 项导入与目录回归通过。实际在新建、已经存在 catalog 的隔离目录导入本机测试模型，启动服务后模型接口返回该模型，空会话创建返回 200；没有调用推理接口。正式供应商、模型、会话和草稿未参与验收。
