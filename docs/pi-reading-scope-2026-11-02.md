# Pi 工具与桌面解读的范围一致性

## 漏项

桌面变更面板此前已分批提供源码材料，但 Pi 的 `change_reading` 工具仍保留另一套请求实现：仅取前 120 个节点、35 个文件，再截取序列化 JSON。用户通过工具或自动 Git 后续阅读进入时，仍可能遗漏后面的文件，或者收到不完整 JSON。这一轮修复入口差异，而不是据桌面已通过推断底层工具也通过。

## 修复与收敛

- 材料打包、请求分批、来源引用校验和部分结果快照移入工程包，桌面与 Pi 工具共用。删除插件内的重复材料实现。
- 每个节点和文件摘要均进入完整 JSON 批次，任务目标随批次提供。超过上下文或 12 批上限时明确失败，不再截取序列化结果。源码片段与差异摘要的裁剪仍有标记。
- Pi 工具保存与桌面相同的可选 `modelCoverage`：实际请求数、有效返回数及节点、文件、关系范围。后续批次失败时保留源码分析和已校验的部分解读，历史重开仍能核对。
- 桌面宿主为 Pi 工具中的每批解读记录现有用量账本，并在请求前核对当前模型授权、只读状态和已有请求限额。取消信号在各批次之间生效。
- 自动阅读失败显示明确的可见消息；显式工具结果标为失败，不把保存了部分来源当作完整解读成功。已经返回失败记录的显式调用不会在同一轮末尾隐式重复一次。

## 证据

1. 新增 Pi 工具测试使用 139 份文件，超过旧的节点/文件上限；实际捕获每批请求并解析完整 JSON，确认所有文件和节点均已提供。
2. 故意让第二批返回无效 JSON，第一批有效章节和全部源码节点保留，记录状态仍为失败。另验证请求限额在派发前阻止调用、取消停止后续工作、自动失败提示和同轮去重。
3. 真实 Ferry 调用通过 Pi 工具读取 139 份新建合成契约文档：5 批、139/139 节点、139/139 文件，436,561 个材料字符；该样本没有裁剪片段。逐文件 SHA-256 核对原文未改变。
4. 真实返回把不可变结果、保留旧版本和并发保护解释为文档要求，没有声称已完成测试。跨批有重复说明，不能据此宣称全局语义归纳已经完善。
5. 每批用量记录、失败用量状态、原对话归属和既有限额通过宿主测试。工程全套 243 项通过，新增取消/失败路径后 5 项 Pi 专项通过；最后 52 项宿主、分批、存储和构建边界检查通过。测试中两个账本字段断言最初不匹配实际协议，已按真实 `status` 和 `attribution` 结构修正后通过。

以上真实模型样本在最后加入目标随批次传递之前完成；文件打包与引用校验逻辑一致，目标字段另外通过范围和 JSON 回归核对。真实模型结果不是任意代码库阅读质量或原生 UI 完整验收的证明。

## 存储登记补齐

复查发现 247–248 的存储登记遗漏，已同步活动可选 `promotedSessionFile`、任务现有 `configRevision` 校验，以及会话转移新增的排他硬链接写入。扫描器纳入硬链接目标写入，更新清单和兼容指纹，数据纪元保持 1。

没有重写既有 JSONL、活动或计划任务。旧版本可能无法从活动条目打开已经移动的旧路径，但普通对话与原始消息仍在。分批结果沿用现有可选范围字段，不引入破坏性数据迁移。

完整目标继续保留原生、外部账号及全局语义归纳的待验范围，不因两入口范围一致而结束全部验收。

正式应用已启用签名的 0.452.249，宿主/服务/界面一致；90 项保护文件无缺失，模型、会话、草稿原样保留，版本纪元和界面时间戳按预期更新。正常单实例运行，没有留下本轮测试服务。
