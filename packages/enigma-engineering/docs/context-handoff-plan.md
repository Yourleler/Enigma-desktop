# 新对话与跨 Agent 上下文交接

确认日期：2026-10-25，Asia/Shanghai。用户希望在同一背景下开启另一项工作，也希望将背景交给 Codex 等其他 Agent。本方案并入当前 Goal 的会话来源交接范围；尚未作为产品能力交付。

## 已验证的宿主能力

Pi 1.4.0 原生支持三种操作：`/tree` 在同一会话内导航；`/fork` 从较早用户消息创建新会话；`/clone` 将当前活动分支复制到新会话。SDK 有 `createBranchedSession()` 和 `forkFrom()`，后者允许目标 cwd 不同。[Pi Sessions](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/sessions.md)、[SDK](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/sdk.md)

本轮对临时会话实际调用 SDK：在公共背景节点分支、排除后面的旧任务、加入新任务，并复制到不同 cwd；原会话文件内容保持不变。该证据证明 Pi 原生接口可用，不证明 Enigma 已完成领域状态或跨 Agent 交接。

当前 Enigma 的 code fork 已传入来源、当前要求和累计消耗，并关联计划，但仍缺少整份 Pi 会话与新工作区的完整启动交接。原生 fork 新建 session ID，也不会自动复制 Enigma 的会话域状态，应补齐适配层。

本机 Codex CLI 0.144.4 支持提示词参数和 stdin；官方非交互接口允许提供任务及附加上下文。App Server 支持 `thread/start` 与 `turn/start` 创建新对话并输入文本，`thread/fork` 复制已有 Codex 历史。没有从本轮官方文档获得“Pi JSONL 直接成为 Codex 原生会话”的证明。[Codex 非交互接口](https://learn.chatgpt.com/docs/non-interactive-mode)、[App Server](https://learn.chatgpt.com/docs/app-server)

ACP 的 `session/new` 和可选 `session/load` 为客户端与同一个 Agent 建立和恢复会话，不能据此声称不同 Agent 的私有历史通用可读。[ACP Session Setup](https://agentclientprotocol.com/protocol/v1/session-setup)

## 产品用途

交接模式要符合用户意图：

| 模式 | 带走什么 | 新任务的行为 |
|---|---|---|
| 沿用背景 | 当前问题相关的项目事实、术语、仓库关系、现行约束和证据 | 用户提供新目标；不自动继续旧 Goal 或旧步骤 |
| 接着做 | 背景、当前计划、完成/阻塞状态、已验证结果和明确下一步 | 接续选定任务，检查实际代码再行动 |
| 比较方案 | 指定节点背景与对应代码基线、已知取舍、证据和待验假设 | 新方案独立记录；需要写代码时使用明确的隔离工作区 |

这项能力与长期记忆配合但职责不同：记忆是可复用知识，交接是本次新任务的选定工作上下文。不能让过去所有细节永久进入新会话。

## 通用交接包

先实现一份宿主无关、可审查、可编辑的本地交接包：

```text
handoff/
  handoff.md          人可读的背景和目标说明，也是任意文本 Agent 的降级入口
  manifest.json       来源、模式、作用域、仓库版本、内容指纹和证据索引
  evidence/           用户选择携带且允许导出的必要证据
```

`handoff.md` 包括选定背景、新目标、适用的当前要求、关键决策及原因、已确认事实、未确认假设、必要文件入口、已做事项、待做事项和有效/失效检查。`manifest.json` 采用独立版本化 schema，保存来源 Agent/会话/节点、导出时点、仓库 ID/逻辑位置/HEAD/分支/源码版本、证据来源和可见性，避免任何一方的私有会话格式成为通用核心。

默认只携带短说明和证据引用，不打包完整源码、聊天、工具日志、隐藏推理、凭证、模型配置或系统提示词。需要额外正文时按用户选定范围导出。导出到别的机器时要求仓库路径映射与必要文件可达；失效路径或缺失来源明确报告，不能伪造完整背景。

对较长会话可在已有授权和预算内生成摘要，但要保留指向原始用户要求和事实依据的入口。摘要只是帮助检索；不能把助手猜测写成已确认事实，不能把原工具结果伪装成目标 Agent 已执行的操作。

## 目标适配与代码状态

Pi 同宿主接续优先调用公开 fork/clone 接口，并补入 Enigma 领域状态。仅沿用背景时优先新建干净会话、导入筛选后的交接说明，避免旧任务惯性。目标会话始终保存来源关联。

Codex 第一版通过现有 CLI 提示词/stdin 或用户在桌面新对话中附加 `handoff.md` 接入；需要自动化管理时使用官方 App Server 创建目标对话并传用户输入。新目标属于用户输入，交接正文作为附加背景数据，不提升为 system/developer 指令。执行命令使用结构化 argv/stdin，不将包内容拼成 shell 代码，不重写 Codex 私有历史目录。

其他 Agent 先提供 Markdown/JSON 的通用出口；能读取文件或接收文本的目标可使用它。逐个验证适配器后再宣称自动启动/接续支持，不能承诺任何 Agent 的运行状态无损迁移。

上下文和代码分开处理：新对话可以继续看原仓库，也可以绑定独立 worktree。创建对话不等于恢复代码。源与目标都准备写同一工作区时需要可见的协调/冲突检查，跨 Agent 无法 enforce 自有锁时优先隔离工作区。导入先核对 HEAD、源码/配置签名和必要证据，旧验收不直接激活；目标 Agent 自己的权限、模型和工具能力保持原有配置，不随交接提升。

源仍运行时，只能选择已经提交的稳定上下文切点，注明未完成操作和未结算效果。写入、恢复和完整方案交接需要正确执行边界；不能仅因为聊天已出现一段回答就当文件操作全部结束。

当前较新的个人纠正、忘记、访问范围和本轮目标继续遵守；旧节点、旧摘要和旧备份不能将已删除记忆重新带入。用户选择“仅背景”时，任务私有状态与旧 Goal 不自动激活。

## 与记忆、观察和审查的结合

- 记忆插件提供按新目标筛选的背景条目和适用条件，减少无关材料；导出前重新核对删除与作用域。
- 观察插件给交接点附上最后稳定阶段、正在执行/未知操作，以及最近有证据的进展，不把日志活性冒充完成。
- 独立审查可使用同一包导入目标、选定 diff、检查结果和来源，无需分享主 Agent 整份上下文。
- 时光机将会话来源与代码快照关联；方案在不同 Agent 中继续探索时仍能追溯和比较。

## 验收与实施顺序

先做 Pi 新背景会话和原生 fork 的领域状态接续，再做通用包，首个外部目标为 Codex。深度 SDK/协议适配按实际收益推进，不增加通用 Agent 编排平台。

验收要求：

1. 从有多仓库背景的 Pi 会话开出不同目标的新会话，新对话能理解选定背景且不继续旧任务；原会话与历史保留。
2. 接着做模式保留最新相关要求、计划来源、未完成事项和累计消耗记录；预算归属明确，不把目标新任务和来源任务的费用混作同一个计数。
3. 至少验证 Pi → Codex 的真实读取与新任务执行，以及 Codex 输出经通用包回到 Pi 的读取流程。来源与目标都检查实际文件、版本和验收，不仅查看输入字符串。
4. 保留来源角色；来源文本中的指令、助手猜测和失败工具结果不能变成目标已执行事实或更高权限规则。
5. 过长上下文、附件缺失、路径迁移、较新用户纠正、删除记忆、运行中导出、未知副作用及并行文件冲突有实际验证。
6. 一键导出/导入有明确目标及模式，支持可查看的降级文案。语义通用与完整原生会话兼容分别报告，不对未适配 Agent 宣称无损接续。
