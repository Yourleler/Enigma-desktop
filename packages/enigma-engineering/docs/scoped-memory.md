# 按需记忆插件

可选记忆插件提供本地知识和经验条目，不重新实现 Pi 会话压缩，也不把整份历史重复加入 system prompt。原始消息、代码和检查仍是事实来源；记忆带来源、适用条件和有效性检查。

## 启用与使用

`enigma-next agent --memory`，或已安装包的原生 `pi --enigma-memory` 启用。单独扩展入口为 `dist/src/pi-memory.js`；默认关闭。与受管协同模式共存，工具为：

- `memory_search`：中文、符号、路径和关键词召回候选摘要，包含命中理由、来源、状态和有效性。
- `memory_read`：按 ID 取正文，核对源文件和检查证据；已忘记、作用域不符或读取期间变化的条目被拒绝。
- `memory_note`：模型保存有源码或有效检查证据的候选知识；不自动认证事实、不写长期个人偏好、不删除或纠正旧条目。
- `history_search`：在当前分支原始用户/助手可见文字中检索，不生成记忆；保留原角色和回查位置，作为轻量替代路径。

用户命令 `/memory-save JSON` 明确保存或纠正条目，`/memory-forget ID [personal]` 忘记，`/memory-find QUERY` 查询。CLI 也提供 `memory save JSON`、`memory search QUERY`、`memory read ID`、`memory forget ID`；CLI 的保存是显式用户操作。示例：

```json
{
  "kind": "contract",
  "scope": { "type": "repositories", "repos": ["library", "sdk"] },
  "title": "公共接口返回值",
  "content": "返回值变化后检查 sdk 消费者，并重新运行联合检查。",
  "appliesWhen": "调整公共接口",
  "tags": ["greet", "返回值"],
  "sources": [
    { "repo": "library", "file": "index.js" },
    { "repo": "sdk", "file": "index.js" }
  ]
}
```

纠正时加 `replaces: MEMORY_ID`；新条目保存后旧条目标为忘记。偏好类记录要求用户显式保存；一次性要求应只作为任务上下文。

中文直接输入支持严格的显式命令：`记住：正文`、`更正记忆：MEMORY_ID 新正文`、`忘记：MEMORY_ID`。仅人类当前输入可触发，不从被读取文档或模型输出执行；一般性的“这次请……”不会自动成为长期偏好。

## 作用域与保鲜

- project：当前项目工作区的知识。
- repositories：全部指定仓库均属于当前工作区时可见，源码锚点由实际文件 hash 决定。
- task：关联 Pi session 和分支节点，只在该节点属于当前活动路径时可见。
- personal：需要用户明确设置 `ENIGMA_PERSONAL_MEMORY` 独立目录；不自动创建全局画像。个人条目不携带项目私有代码或检查引用。

支持约定、跨仓库契约、方案决策、排障、偏好和研究笔记。来源区分用户陈述与助手/源码/研究记录；`candidate` 和 `user-stated` 都不是已完成任务的验收。

正文放在 `.enigma-next/memory/entries/*.md`，机器元数据和修订放在相邻 JSON。人可编辑正文；手改后的正文可搜索，但标为 stale，需显式重新保存才成为当前版本。源码变化、证据失效或缺失同样标为 stale/unavailable，默认召回排除过期内容，可显式查看其理由。

删除先发布单调的 forgotten 标记；即使删除时中断、旧 pointer 尚未推进，也不能再次召回。代码检查点不包括记忆运行目录，恢复旧代码不会恢复被忘记的条目。当前存储保留修订元数据供检查，忘记是停止检索和使用，不等于安全擦除所有历史备份。

可识别的旧 `memory_read` 正文和 `memory_search` 摘要在后续模型上下文中会重新检查忘记与作用域；旧工具记录仍保存在原始日志，但不作为已删除的知识再次送给模型。无法从任意历史文字逆向识别所有同义转述，原始会话不是安全擦除对象。

## 成本与限制

当前用本地词法与中文二字片段检索，不需要 embedding 服务或额外模型调用。条目正文按需读取，默认 6 项、最多 20 项；单正文写入 24,000 字符、读取 64 KB，单库最多 500 项。阶段事件用于测量 memory.search/read/write 耗时。

可重建 `search-index.json` 先保存词项与摘要，文件元数据变化时重建相关条目；实际命中的正文仍核对内容版本、来源和删除状态。`memory reindex` 可强制重建；派生索引损坏可从正文恢复。

`memory_note` 的 `defer: true` 先形成未召回草稿。空闲时 `/memory-organize` 或 `memory organize` 有界核对来源、去重建议和索引；来源已变草稿不提升。处理中的未结算草稿不自动重放，避免重复晋升。该整理不调用模型，不自动删除重复条目。

`memory recover` 只释放确认已退出的写入者锁，将未结算处理草稿标为 unknown；活跃写入者锁不会被抢走，未知草稿不会自动重新提升。

错误签名或同一版源码读取连续三次才触发困难建议；每次运行最多两组，30 秒冷却。只推荐当前作用域与来源版本有效的少量索引，正文需主动读取；没有相关记忆不加上下文。详细记忆首次读取会提供正文，之后用引用替代重复正文，不删原始历史、不重放操作。

真实小样本对照中，三种条件各两个文档任务均成功，轻量记忆没有显示更快；建库约 17 ms，但多了召回工具调用。继续默认关闭、按需启用，不宣称普遍收益。详见 [记忆对照](memory-comparison.md)。跨机器记忆共享与通用图谱平台不属于本版。
