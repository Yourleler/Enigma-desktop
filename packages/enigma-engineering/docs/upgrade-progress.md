## 运行观察首轮实现

可选 `pi-observer` 已接入 Pi 请求/响应/流、工具、命令、用户交互、压缩和收尾事件；领域层通过轻量 sink 提供工作区、快照、阅读、验收与真实变化的阶段证据。默认关闭，不重新实现主 agent loop。

`agent --observe` 启用；另一终端 `status` / `why-slow` 不创建 Workspace、不获取操作锁、不调用主模型。快照和日志有界，写入失败不能改变任务执行。状态区分进程活性、观测新鲜度、证据变化与疑似重复行为。

实际测试证明：命令持有真实工作区锁时旁路查询能在释放命令前完成；Pi 延迟 HTTP 响应期间独立查看等待阶段；重复源码版本不变与流事件不冒充新证据；SIGKILL 后识别来源已终止；启动身份不一致不信任旧 PID。源码正文、原始模型流和已声明密钥不进入镜像。

首轮新增 5 项测试，当前完整回归 50 项通过。自然语言模型解释、更多故障阶段、实时进展的任务关联、真实 Gateway 与观测驱动性能优化仍需后续验证；记忆插件和跨 Agent 交接尚未实现。

## 首批观测驱动优化

真实三仓库命令测量发现每次执行有 8 次仓库快照：全工作区前后各三次，加上当前仓库的重复前后采集。移除重复采集后变为 6 次，保留所有仓库效果覆盖。测量记录在 `<LOCAL_AUDIT_ROOT>/2026-10-25/enigma-next-validation/observer-performance/`，耗时属于同类临时工作负载的小样本，不代表真实任务普遍加速。

显式 `workspace_verify` 通过后，收尾先重查该证据的源码、配置、环境及未知操作状态；仍有效时复用，避免重新执行相同检查。证据过期、验收规则变化或未知执行效果禁止复用。实际检查计数证明正常收尾只运行一次；外部源码在检查后改变时收尾重新运行。新增 3 项测试，完整回归 53 项通过。
