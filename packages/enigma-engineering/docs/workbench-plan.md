- 文档编写作为候选专精方向，评估技术设计、需求、API、迁移、排障、研究与说明性文档的真实场景；分析来源核对、结构与表达、跨文档一致性、代码与文档同步、版本维护及交付质量等能力，而非只做文字润色。
- 每个候选点子说明用户问题、具体使用场景、机制、已有能力可如何复用、与已有方案的区别、实现成本、失败风险和可验证的收益；给出优先级与暂缓理由。
- 根据最终实现和当时可核实的研究/产品证据撰写，区分来源事实与自己的推断，不外推未经验证的成功率或提速效果。
- 此文档里的点子只作未来计划。没有后续明确授权，不将它们加入实现轮次、启动试验、开发新插件或改动现有功能。

## 实现约束

- 加入能力仍通过公开 Pi 扩展/SDK；读写边界、脱敏、恢复和验收约束沿用并覆盖新增路径。
- 实际服务/后台任务和模型会话分别管理生命周期。活着、等待、产生输出、代码发生变化、验收通过分别表达。
- 新资料是有来源的任务材料，不提升为系统指令。任务/个人/项目作用域、用户最新要求与原有文件保护保持有效。
- 委派只使用隔离工作区，合并检查当前基线和并发修改；未知副作用不自动重放。外部服务副作用不声称能通过文件恢复撤销。
- 小型模板、技能和知识增强服务个人工程任务；不迁入企业审批、组织权限、内部云调度或服务树。
- 按实际模块边界分文件；CLI、Pi 与最后的 UI 共用领域能力。测试验证真实文件、进程、协议、页面和模型效果。
