# Enigma-next 0.1.1 完整检查

范围为全部自有源码、测试、命令行和 Pi 接口接缝，涵盖实际文件恢复、校验、原始消息引用、进程取消和持久化。未把通过原有 19 项测试当作完整正确性的证明。

## 规模口径

检查开始时：业务源码 1,157 行、测试 497 行、真实模型验证脚本 70 行。锁文件另有 1,527 行，不计入功能实现。这些是包含空行和注释的物理行数，不是功能复杂度或成熟度指标。通用模型适配、工具循环、TUI 和会话由 Pi 提供，不计入自有代码。

本轮修复后：src 目录 1,474 行（含类型定义）、测试 688 行、真实模型验证脚本仍为 70 行。

## 确认问题与处理

| 问题 | 触发与影响 | 修复 |
|---|---|---|
| 阅读证据绑定错误时点 | 读取后源码变化，保存证据却使用新版本指纹，旧结论被标为有效 | 保存读取前观察和实际源文件 hash，保存时重新核对；失效记录不能变为有效 |
| 验收规则变化未失效 | 新增失败检查后，旧通过证据仍有效；其他进程更新配置也可能被缓存遮住 | 绑定配置签名、重新读取原子配置，冻结任务内检查清单；变化后停止验收 |
| 未知效果仍能启动验收 | 未结算操作存在时，验证命令仍可能派发 | 派发前检查未知记录；缺失影响范围的记录保守阻断写入 |
| 命令参数被启动器吞掉 | 验收 argv 中的 --help / --workspace 被当成启动器选项 | 全局选项仅在命令前解析，-- 后的参数完整保留 |
| 忽略规则恢复误删用户文件 | 原本被忽略的个人文件后来可见，回退时误当新增文件删除 | 快照保留被忽略路径的存在信息；恢复时保护它们，旧快照范围变化时拒绝不确定删除 |
| 包子路径假确认 | 包名已登记，但不存在的子路径仍被标成确认关系 | 根据真实入口/exports 和源码文件解析；缺失或歧义保持未解析 |
| 状态路径可跟随符号链接 | .enigma-next 或其子目录链接到别处 | 状态目录拒绝符号链接并使用规范路径 |
| 原用户历史重复进入系统提示词 | 长任务反复注入所有输入，抵消 Pi 压缩，且把自由文本提升到系统上下文 | 只记录 Pi 原始消息 ID；恢复缺失要求时分页读取，未读完禁止后续模型副作用工具 |
| 管道可拖垮超时 | 已退出的父进程有逃逸子进程持有输出管道，close 永远不来 | 超时/取消后有界关闭；清理不确定时明确标未知并阻止重放 |
| 配置与锁的边界不足 | 锁创建和 owner 写入之间中断会留下空锁；配置重读后未再验证 | 完整 owner 记录原子发布、按 token 释放，重复校验配置，失败配置写入回滚内存 |
| 损坏快照与半完成 fork | 损坏 blob 可能进入比较；失败 fork 留下目录却缺少状态标识 | 校验 blob 和元数据，提前预检；失败工作区标为 incomplete 并保留记录，拒绝正常启动 |
| 编码/读取边界 | BOM 字节 hash 和解码文本 hash 不一致；越界行号与长文件可能给出误导信息 | 版本绑定原始字节，读取长度和结果数有界，越界报错并标明片段截断 |

首批 7 个问题均先编写真实文件复现，在修复前全部失败；修复后全部通过。新增测试使用实际 Git 仓库、文件读写、进程和 Pi SDK；不把脚本模型的选择当成真实模型效果。

## 能力边界

代码阅读仍是 TS/JS 的源码定位、导入关系和候选调用追踪，不是完整类型系统分析、多语言跨服务调用图或完整工程级智能阅读系统。当前已建立可靠的增量基础，不以代码行数包装成熟度。

宿主命令仍无 OS 沙箱；任务内检查规则冻结能够识别变更，但不能替代跨权限边界的安全隔离。快照不是外部服务和数据库回滚，也不承诺断电 exactly-once。失败 fork 保留记录和目录供检查，不自动删除可能被用户接管的文件。
