## 研究依据与取舍



旧 Enigma 的记忆模块（本地参考文件）已有工作/情景/持久记忆、problem/applies_when、中文与词法召回、主题索引、源码指纹失效；运行模块（本地参考文件）还有任务结束/压缩附近的模型反思。应保留适用条件与保鲜机制，重新设计增量记录和调度，避免重复历史与频繁模型反思。


近期研究提供不同线索：

| 来源 | 可以提取的机制 | 本项目的限制 |
|---|---|---|
| [REM，2026-10-19](https://arxiv.org/abs/2610.27377) | 经验分阶段整理；运行中出现困难才取详细记录；控制一次暴露后的常驻占用 | 在编码基准的预印本结果不证明本项目收益；不复制自动整轨迹总结与默认启动注入 |
| [MemCode，2026-10-14](https://arxiv.org/abs/2610.19472) | 把记忆写成自包含单元；在线写入与后台整合分离 | 先采用条目和关系索引，暂不训练离散码本 |
| [MemCodex，2026-09-30](https://arxiv.org/abs/2609.39765) | 从概览到关系与原始证据逐层读取，足够时停止展开 | 不加入自动改写记忆程序、提示词或工具实现的机制 |
| [MemRL](https://arxiv.org/abs/2601.03192)、[ReasoningBank](https://arxiv.org/abs/2509.25140) | 先筛相关性，再参考有结果反馈的经验效用；成功与失败都可形成教训 | 本项目使用真实检查反馈和适用条件，不先建设 RL 系统，不把模型自评当成功证据 |
| [MemoryTax，2026-10-21](https://arxiv.org/abs/2610.29823) | 计入建库、维护、检索和使用的总成本；保留可搜索原始历史作为基线 | 该研究仅一个 LoCoMo 对话、每格一次运行，且证据可见性有差异，不能据此断言记忆普遍无用 |

上述研究和工程案例支持小规模、可回查、按需的实现路线。效果必须在本项目相关连续任务中验证，不引用论文数字作为产品收益。

## 记忆插件

### 记忆内容与作用域

一个可选插件提供四种有明确用途的记忆，而非多套独立数据库：

1. **仓库与跨仓库关系**：入口、接口/数据契约、生产方、消费者、联合检查、构建约定。关系同时引用相关仓库与源码/配置版本；上游变更使相关结论重新待验。
2. **任务与方案决策**：采用某方案的原因、排除条件、已解决阻塞和未确认问题。绑定任务/会话分支与代码证据；方案探索不能自动覆盖全局项目事实。
3. **排障与操作经验**：错误征象、失败尝试、原因、适用条件和有效检查。借鉴旧 Enigma 的 problem/applies_when；证据未确认时保留为候选，避免重新尝试已经证明无效的方法。
4. **个人偏好与非代码知识**：显式长期偏好、项目外的可复用研究结论和环境经验。一次性要求只属于任务，检索范围由用户或当前项目明确确定；跨项目个人记忆按用户配置启用。

每条记录保留 ID、类型、作用域、摘要、适用条件、来源、版本/有效条件、验证状态、替代关系和删除状态。原始 Pi 对话与已有阅读/检查产物保持原有归属，记忆引用它们，不复制完整历史。不把来源文本或旧记忆提升为 system 指令；当前用户要求、实际代码和现行权限保持权威。

### 检索、更新与恢复

小索引先返回摘要、命中理由和证据入口，正文按需取用。先实现精确名称/路径/代码符号与中文词法召回，必要时再接可选语义检索；没有 embedding 服务仍可用。索引可重建，人可查看、编辑、纠正和删除正文。

可确定的工具证据及时记录；复杂经验先形成草稿，空闲时有界整理。去重、失败、超时和取消不能阻塞主任务收尾。后台工作需有自己的状态、预算、来源和失效检查，不能使用旧快照整档覆盖新记忆。明确的“记住/纠正/忘记”请求在已授权范围内执行，无需额外重复确认；自动提炼一次性要求不能变成长期偏好。

分支记忆随方案关联；较新个人纠正、删除和权限不能随代码或对话回退而复活。代码相关记忆恢复后按实际版本重新检查。长期知识与任务状态分别表达，不能用过去成功记录替代当前验收。

## 运行观察插件

### 事实、活性与进展

观察插件监听 Pi 公开生命周期和自有工具阶段事件。Pi 已提供模型请求、响应、流事件、工具开始/更新/结束与收尾事件；部分 provider 不暴露全部传输阶段，缺失必须如实表达。[Pi 事件契约](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/extensions.md)

最少记录：run/session/request/tool/process 的关联 ID、阶段、开始与最近事件时间、结束状态、耗时、来源仓库、重试/等待原因、输出活动、代码/阅读/检查证据变化及采集范围。参数和输出默认只保存必要的脱敏摘要，原始正文按现有产物回查。可借鉴 OpenTelemetry 的操作 span 与因果关联，不把开发中的语义约定作为稳定持久格式。[OpenTelemetry GenAI spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md)、[Agent spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md)

三个问题分别回答：

- **在做什么**：准备上下文、读取记忆、等待模型首个可见响应、接收流、读代码、执行命令、等待审批、检查点、验收、重试或收尾。
- **是否仍活着**：真实执行句柄/进程身份、事件和输出是否在更新。进程活着、CPU 或 token 增长不能证明有意义进展；事件静默也不能直接证明死锁。
- **有没有推进**：发现新源码依据、排除有证据的失败假设、完成必要修改、通过检查或解除依赖阻塞。重复读取同一版内容、相同错误循环和无新证据的重试只构成疑似低效信号，需要结合任务阶段解释。

未知情况使用“无法确认”，例如 HTTP 请求未返回时只能说正在等待响应；没有服务端遥测不能说一定在模型排队、prefill 或内部推理。观察员不解释隐藏思维链，回答基于可见事件和产物。

### 独立查询通道

用户在主 Agent 运行期间，能从另一终端或只读旁路查询 `status`、`why-slow` 或自然语言问题，得到阶段、持续时间、最后一次有证据的进展、疑似问题、证据入口和建议。名称在实现时确定。

独立查询读取增量事件镜像与状态快照，不能获取工作区排他锁、等待主模型回合完成或把问题排入主任务队列。事件镜像有界、可恢复；主进程卡住时旁路仍能区分“进程存在但观测停止”和“来源已终止”。PID 重用、进程重启、事件缺失、日志部分写入和未知子进程清理应显示真实限制。

默认确定性摘要，用户需要时可调用一个有界的说明模型读取状态。旁路模型可能与主任务共享 Gateway 的限额，应有独立预算和取消，不默认持续占用模型。观察失败不能改变工具结果或阻止原任务执行；建议不会自动恢复、重放、杀进程或改写代码。

## 慢运行优化与记忆联动

先测量端到端耗时与阶段耗时，优先定位已有代码的具体开销：

- `workspace.ts` 的全仓库快照、读取证据后重复计算指纹、一个命令前后单仓及全工作区重复采集。
- `planning.ts` 为多项证据分别检查全工作区。
- `pi-extension.ts` 显式 `workspace_verify` 后在收尾再跑全部检查。
- TypeScript 阅读中的重复 program 构建，以及无需变化的索引重建、记忆提取和召回。

静态调用链只证明这些操作存在，不证明其耗时占比。优化基于观测：同一稳定观察范围内共享一次采集、复用当前版本的有效检查、受影响子图与配置签名驱动增量、减少重复上下文与工具暴露、有界并行独立读取。外部编辑、命令副作用、未知依赖、环境或验收配置变化时重新核对，不能以缓存或加速削弱正确性。

观察员发现困难时，按具体错误、当前源码版本和适用范围召回少量相关经验。召回有去重、冷却与输出预算；每条解释为什么相关以及是否仍有效。没有相关结果就不添加内容。详细经验用完不继续反复注入；不会每次慢响应都触发额外大模型反思。

## 实施顺序与验收

先交付运行事件与独立查询，为已有性能问题建立证据；再交付小型记忆存储、作用域、词法/中文召回、纠正删除与版本保鲜；最后加入困难触发召回和有数据支持的优化。两个可选插件共用轻量事件与证据接口，与核心协同插件可分别加载、关闭和移除，不新增通用工作流平台。

验收增加：

1. 连续多仓库任务能复用契约与排障经验；上游代码/配置变化、中文模糊追问、同名仓库隔离、无结果和不相关记忆都有实际案例。
2. 稳定偏好、一次性要求、纠正、忘记、来源不可信和分支回退分别验证；删除的记忆不能因恢复旧方案而再次召回，缺失原始证据不能假装已确认。
3. 主 Agent 在等待模型、运行静默长命令、输出持续变化、等待审批、重试、被取消、强杀或观测中断时，旁路无需等待主任务即可回答；使用实际进程/请求和来源句柄验证。
4. 正常的长计算不能因静默被误报为确定卡死；相同文件版本反复读取/错误循环可解释，任何“有意义进展”结论有产物或任务依据。
5. 记录观察与记忆插件自身开销，以及同类任务关闭记忆、仅查询原始历史、启用轻量记忆的端到端时间、检索/写入/建库成本、任务结果和误召回。小样本如实报告，不要求或伪造普遍加速；无收益的策略不默认启用。
6. 性能改动继续通过外部改动、证据失效、验收规则冻结、未知副作用、取消、强杀、部分恢复与三平台回归；现有 Gateway 完成真实多仓库和跨会话联调。
