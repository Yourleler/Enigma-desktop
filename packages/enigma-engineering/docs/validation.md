## 真实模型联调

完成两类实际模型任务：

1. Pi SDK → Gateway Responses：公共库 API 返回值变化，模型自行读取源码并修改公共库、SDK、应用三个仓库。最终运行三项语法检查和一项真实联合运行检查，全部通过。0.1.1 修复后的验证运行观察到 11 次工具调用及 45 个文本流片段。
2. 原生 Pi CLI → Gateway Responses：只读定位导入链，执行相同联合检查并报告结果。实际进程正常结束，未修改源码。

真实 SDK 运行可通过 npm run build 后执行 node scripts/gateway-probe.mjs 新的验证目录复验。该脚本只在用户显式运行时调用真实模型，CI 不会调用。

受控 FauxProvider 和 HTTP fixture 用于注入拒绝、提前结束等情况；这些结果证明机制和状态契约，不代表真实模型效果。上述真实任务数量很小，不是成功率 benchmark，也不证明所有仓库、模型或语言都已可靠。

## 已知限制

- 代码阅读当前公开支持 TypeScript/JavaScript，动态调用和未解析符号仍需继续读取源码。Python/Go 解析器不在此版本中。
- 检查指纹使用整个注册工作区和执行环境，失效策略保守，可能重复检查。
- 宿主命令有审批、超时和取消，没有 OS 沙箱；数据库、服务、网络等外部操作不能通过文件快照回滚。
- 文件快照支持普通文件，排除凭证和依赖目录；单仓上限 256 MiB/50,000 个文件。
- 多仓库恢复不是分布式事务；失败或进程中断有记录和观察机制，不宣称断电场景的 exactly-once。
- Code fork 保留来源 Pi 节点和领域要求，不自动迁移整份 Pi 会话到新目录。新目录启动新会话，当前会话内的上下文恢复仍使用 /enigma-restore。
兼容 API 的可用性由本项目实际联调验证；宿主或供应商升级后应复验。

多平台 CI 结果在推送后确认；不以本机测试替代远端结果。
